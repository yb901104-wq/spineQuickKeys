### ① PMA 控件：改为两个独立复选框（用户已确认）

#### 症状

控制条只有一个 `_chkPma`（「PMA 预乘」），无法对应导出时的多种纹理打包设置。

#### 根因

- `bridge.js:171`：`premultipliedAlpha: g.premultipliedAlpha !== false` —— 桥接层只消费一个布尔。
- `ExportPreviewWindow.cs:46, 330`：`private readonly CheckBox _chkPma`；`_chkPma.Text = "PMA 预乘"`。
- `ExportPreviewSettings.cs`：设置项 `bool PremultipliedAlpha`，只有二态。

#### 必须先说明的技术事实（不能做成「三种渲染效果」）

Spine 导出时「**预乘 / Premultiply alpha**」与「**溢出 / Bleed**」是 Texture Packer 的**两个独立设置**：

| 设置 | 作用阶段 | 运行时是否需要区分 |
|---|---|---|
| 预乘 Premultiply alpha | 导出：RGB 预先乘上 A | **需要** —— 决定 WebGL 混合模式 `premultipliedAlpha` |
| 溢出 Bleed | 导出：把透明边缘像素颜色向外扩边，避免线性过滤出现黑边 | **不需要** —— 效果已烘进 PNG 像素，运行时读到的是最终结果 |

因此「溢出」与「都不选」在渲染上**完全等价**；运行时只能二态。UI 提供多态的意义是**与导出设置一一对齐、便于核对**，而不是渲染出多种画面。这一点需在界面上明示，避免误导。

#### 修复步骤（用户已选：两个独立复选框，与 Spine 导出面板同构）

1. 保留 `_chkPma`，文案改为 `预乘(PMA)`；新增 `_chkBleed`，文案 `溢出(Bleed)`。
2. 两个复选框的状态映射：

   | 预乘 | 溢出 | 传给 runtime 的 `premultipliedAlpha` | 说明 |
   |---|---|---|---|
   | ✓ | ✗ | `true` | 用户描述的第 1 种 |
   | ✗ | ✓ | `false` | 用户描述的第 2 种；Bleed 已在 PNG，运行时按 straight 渲染 |
   | ✗ | ✗ | `false` | 用户描述的第 3 种 |
   | ✓ | ✓ | `true` | **双复选框天然可表达的第 4 种**，Spine 导出面板允许同时勾选；运行时仍只按「预乘」渲染 |

   > 若你要求严格互斥三态（禁止「两个都选」），需在施工前另行说明；当前方案按「与导出面板同构」允许 4 态。

3. 新增 `ToolTip` 或行内提示：`溢出(Bleed) 为导出期像素扩边，已烘入 PNG，运行时与「都不选」等价；仅「预乘」影响混合模式。`
4. 设置持久化：复用现有 `bool PremultipliedAlpha`，新增 `bool Bleed`；读取旧设置文件时 `Bleed` 缺省 `false`，**保证向后兼容**。
5. `_chkBleed` 的 `CheckedChanged` 只写设置、不触发 player 重建（因为它不改变渲染）；`_chkPma` 沿用现有 `loadGroup` 重建逻辑。
6. 新增复选框带来的控制条空间压力，与 ② 的布局重排**一并解决**（见下）。

#### 涉及文件

`ExportPreviewWindow.cs`、`ExportPreviewSettings.cs`、`bridge.js`（仅注释/字段透传）。

#### 验收

- 4 种组合均可勾选并持久化，重启后恢复。
- 仅切「溢出」不重建 player、不中断播放；切「预乘」正常重建且渲染变化符合预期。
- 界面提示文案可见，不会让用户误以为三态有三种渲染结果。

### ② 控制条底部被裁切

#### 症状

截图 1：控制条中按钮文字换行、底部被裁，控制条下方还露出半行被截断的 UI。

#### 根因（数值链，已实测代码确认）

| 位置 | 值 |
|---|---|
| `UiTheme.cs:108` | `UiWindowProfile.ExportPreview => (new Size(1440, 900), new Size(1040, 680))`，第二项为 **MinimumSize** |
| `ExportPreviewWindow.cs:56` | 构造函数调用 `UiTheme.Apply(this, UiWindowProfile.ExportPreview)` → 该窗体 `MinimumSize = 1040×680` |
| `MainForm.cs:43-44` | `ClientSize = 1440×900`，`MinimumSize = 1100×650` |
| `MainForm.cs:1113-1122` | `EmbedPage`：`form.TopLevel = false; form.Dock = DockStyle.Fill; page.Controls.Add(form)` |

**成因**：`ExportPreviewWindow` 以非顶层 Form 嵌入 TabPage 后，WinForms 仍强制其 `Size >= MinimumSize`。当用户把主窗口缩小到最小 `1100×650`，TabPage 可视高度约为 `650 − 标签头(~34) − 边框/内边距 ≈ 600`，小于嵌入窗体的 `MinimumSize.Height = 680`。`Dock=Fill` 无法把窗体压到 MinimumSize 以下，超出的约 80px 被 TabPage 裁掉 —— 正好是控制条 `84px` 的高度，与截图完全吻合。

**次生症状**：`_btnReset.Text = "⏮ 归零"`（`:384`）、`_btnSetup.Text = "Setup Pose"`（`:385`）在列宽 `70 / 92`（`:371-372`）下换行，叠加高度不足后显得更严重。

#### 修复步骤

1. **主修复**：`EmbedPage` 增加可选参数 `clearMinimumSize`，仅在 `EnsureEmbeddedPage(3)`（预览页）传 `true`，在 `Dock=Fill` 之后执行 `form.MinimumSize = Size.Empty`。嵌入子窗体的尺寸应完全由 TabPage 决定，MinimumSize 对嵌入形态有害无益。
   - **范围约束**：只清预览页，不碰另外两个嵌入页（改名工具、批量 CLI），避免影响既有布局。
   - **不改** `MainForm.MinimumSize`（会影响全部 4 个主分页，超出本次范围）。
2. **按钮单行化**：`_btnReset` / `_btnSetup` 设 `AutoSize = false`、`TextAlign = MiddleCenter`，文案缩短为 `归零` / `Setup`（完整语义放 ToolTip），固定高度 26，杜绝换行。
3. **控制条高度对齐**：`BuildRightColumn`（`:255-258`）第三行 `Absolute 84` 与 `BuildControls`（`:326-327`）两行 `36 + 46 = 82` 保持，预留 2px；不新增行，避免挤压画布。
4. **容纳 ① 的新复选框**：`row1`（`:329`）取消 `速度` / `Mix` 两个独立文字标签，改由下拉框 `ToolTip` 承载；把 `_lblCurrent`（当前摘要）从 `row1` 移到右列顶部信息条（该处已有 `_lblInfo` / `_lblVersion` / `_lblCompanion` / `_lblStatePill`）。腾出的宽度放入 `_chkBleed`。
5. **③ ⑤ 新增按钮不占控制条**：改为画布右上角浮动小工具条（`_canvasHost` 内 `Anchor = Top|Right`），见 ③ ⑤。
6. `row2`（`:367-373`）保持 6 列不变，第 6 列 `Absolute 0` 的占位保留或移除均可，不新增控件。

#### 涉及文件

`MainForm.cs`（`EmbedPage` / `EnsureEmbeddedPage`）、`ExportPreviewWindow.cs`（`BuildRightColumn` / `BuildControls`）。

#### 验收

- 主窗口缩到最小 `1100×650`：控制条完整可见、无文字换行、无半行截断 UI、浮动工具条不被裁。

### ③ 滚轮缩放 / 拖拽平移 / 复位视图

#### 症状

画布内动画不能用滚轮放大缩小，也不能拖拽移动位置；缺少复位按钮。

#### 根因（含一处对前述判断的更正）

排查中曾判断「`interactive: false` 关掉了官方滚轮缩放」——**该判断错误，特此更正**。实测三个内置 runtime：

| 检查项 | 4.1 | 4.2 | 4.3 |
|---|---|---|---|
| `CameraController` 类定义 | 有 | 有 | 有 |
| `new CameraController(...)` 调用次数 | **0** | **0** | **0** |
| `config.interactive` 出现次数 | 0 | 3 | 3 |
| `this.bg.setFromString` | 1 | 1 | 1 |

`CameraController`（`spine-webgl/src/CameraController.ts`）确实实现了 `wheel` 缩放与 `dragged` 平移，但 **`SpinePlayer` 从未实例化它**。`config.interactive` 只控制 `setupInput()` 中「控制骨骼（control bones）」的拖拽与点击暂停，与相机缩放无关。因此**官方 Web Player 本身没有滚轮缩放/平移能力，必须自行实现**。

**第二个硬约束**：`SpinePlayer.drawFrame()` 每帧都重新计算相机：

```js
renderer.camera.zoom = this.canvas.height / this.canvas.width > viewport.height / viewport.width
    ? viewport.width / this.canvas.width : viewport.height / this.canvas.height;
renderer.camera.position.x = viewport.x + viewport.width / 2;
renderer.camera.position.y = viewport.y + viewport.height / 2;
```

即 `camera.zoom` / `camera.position` 每帧被 `currentViewport` 覆盖。**直接改 camera 会在下一帧失效**，缩放/平移必须落在 `player.currentViewport` 的 `x / y / width / height` 上。

#### 修复步骤（全部在 `bridge.js`，不改内置官方 runtime 文件）

1. 维护模块级视图状态 `view = { zoom: 1, panX: 0, panY: 0 }` 与 `baseViewport = null`。
2. 首次 `ready` / 首个 `onFrame`（`player.currentViewport` 已为有限值）时，快照 `{ x, y, width, height }` 为 `baseViewport`。
3. 包装 `player.drawFrame`：调用原方法前执行 `applyView()` —— 以 `baseViewport` 为基准，按 `view.zoom` 缩放 `width/height`（保持中心），叠加 `panX/panY` 到 `x/y`，写回 `player.currentViewport`，**保留原有 `padLeft/padRight/padTop/padBottom` 字段**。
4. 在 canvas 上挂原生监听：`wheel`（`preventDefault`，以鼠标位置为锚改 `zoom`）、`pointerdown` / `pointermove` / `pointerup`（拖拽改 `panX/panY`）。像素→世界坐标换算按 `baseViewport.width / canvas.clientWidth / view.zoom` 推导，避免依赖 runtime 内部类。
5. `zoom` 限幅 `0.1 ~ 10`；`pan` 不限但可一键复位。
6. 新增 C# → JS 消息 `resetView`：`view` 归零并以当前 `baseViewport` 重绘。
7. `loadGroup`（切换文件）时重置 `view` 与 `baseViewport`。
8. UI：画布右上角浮动工具条新增 `⟲ 复位视图` 按钮（见 ② 步骤 5），不占控制条高度。

#### 涉及文件

`bridge.js`、`SpinePlayerHost.cs`（新增 `ResetView()` 发送消息）、`ExportPreviewWindow.cs`（浮动工具条）。

#### 验收

- 4.1 / 4.2 / 4.3 三套 runtime 各测：滚轮放大 / 缩小、按住拖拽平移、点击复位回到初始视图。
- 缩放锚点跟随鼠标；`zoom` 边界不出现 NaN / 画面翻转。
- 播放中操作不中断动画；暂停态 seek 后视图保持。

### ④ 切换动画时缩放与位置不统一

#### 症状

同一角色切换不同动画时，每次自动使用不同的缩放倍率与位置，难以对比观察。

#### 根因

三个版本 runtime 一致，`SpinePlayer.setAnimation` 的实现为：

```js
/* Sets a new animation and viewport on track 0. */
setAnimation(animation, loop = true) {
  animation = this.setViewport(animation);
  return this.animationState.setAnimationWith(0, animation, loop);
}
```

`setViewport(animation)` 内部会：

1. `this.previousViewport = this.currentViewport;`
2. `this.currentViewport = { padLeft, padRight, padTop, padBottom, ... }` —— **重新赋值整个对象**；
3. 调用 `calculateAnimationViewport(animation, viewport)`，按**该动画 100 帧采样的包围盒**重算 `x/y/width/height`；
4. 设置 `viewportTransitionStart = performance.now()`，触发过渡插值。

`bridge.js:265` 的 `case "setAnimation"` 直接调用 `player.setAnimation(m.name, loop)`，因此每次切动画都丢掉用户视图。`setLoop` 分支（`:282`）同样二次调用 `setAnimation`，也会重算。

#### 修复步骤（与 ③ 共用 `view` / `baseViewport`）

1. 已确认 `setViewport()` 结尾 `return animation;` —— 可安全包装，返回值必须仍是 animation 对象（否则 `setAnimationWith` 会收到错误参数）。
2. 在 `loadGroup` 创建 player 后包装 `player.setViewport`：
   - **放行条件**：`baseViewport == null`（首次），或 `currentViewport` 存在非有限值（`NaN` / `Infinity`）—— 后者是 **V3.1 修复 4.1 空白画布的根因场景**，必须保留重算能力，不得锁死。
   - **锁定后**：直接 `return (typeof animation === "string" ? p.skeleton.data.findAnimation(animation) : animation)`，**不调用原方法、不修改 `currentViewport`**。
3. 放行原方法后，若结果 viewport 为有限值，则记录/更新 `baseViewport` 并置锁；同时把 `player.previousViewport = null`，消除过渡插值造成的视图漂移。
4. 切动画 / 切皮肤 / 切循环 / seek 均保持 `view` 不变；切文件（`loadGroup`）重置锁与 `view`。
5. 「复位视图」= `view` 归零 + 按 `baseViewport` 重绘（与 ③ 步骤 6 同一入口）。

#### 涉及文件

`bridge.js`（与 ③ 同一处改造）、`ExportPreviewWindow.cs`（无需额外改动，沿用现有列表事件）。

#### 验收

- 用 `ExecuteScriptAsync` 探针断言：同一文件连续切换 3 个动画前后，`currentViewport.x/y/width/height` 与 `camera.zoom/position` **数值完全一致**（误差 0）。
- 用户手动缩放/拖拽后再切动画，视图保持；点击复位回到首次加载基准。
- **回归 V3.1 的 4.1 修复**：用户真实工程 `G2.skel.bytes`（`D:/动画工程/monster-spine-h细线/导出/`）加载后仍出现可见角色，皮肤 `1` → `2` 视觉变化正常，不得回到空白画布。

### ⑤ 多档背景切换

#### 症状

画布背景只有一种深色，对不同色调角色不便观察。

#### 根因

`bridge.js:173` 硬编码 `backgroundColor: "1E1E20"`。runtime 在资产加载阶段执行一次：

```js
this.bg.setFromString(config.backgroundColor);
this.bgFullscreen.setFromString(config.fullScreenBackgroundColor);
```

之后 `drawFrame()` 每帧用 `gl.clearColor(bg.r, bg.g, bg.b, bg.a)` 清屏。因为 `bg` 是缓存的 `Color` 对象，**切换背景无需重建 player**。

#### 修复步骤

1. 新增 C# → JS 消息 `setBackground`，携带 6 位 hex 字符串。

### ⑥ 虚拟按键窗口最小尺寸不贴合按钮

#### 症状

截图 2：窗口高度已拖到可拖动的最短，但按钮四周仍有明显富余留白；长宽最小尺寸与按钮网格不贴合。

#### 根因

| 位置 | 代码 | 问题 |
|---|---|---|
| `VirtualKeyWindow.cs:626` | `Size = new Size(Math.Max(160, ...), Math.Max(100, ...))` | 拖拽下限是**硬编码常量**，与按钮实际内容无关 |
| `VirtualKeyWindow.cs:882` | `Size = new Size(Math.Max(160, margin*2+contentW+ncW), Math.Max(100, margin*2+contentH+ncH))` | 自适应贴合同样被 160/100 硬下限截住 |
| `VirtualKeyWindow.cs:867` | `columns = ceil(sqrt(n * max(0.5, ClientSize.Width / ClientSize.Height)))` | AutoGrid 列数依赖**当前窗口宽高比**：窗口变高 → 比值变小 → 列数变少 → 行数变多 |
| `VirtualKeyWindow.cs:849-851` | `margin = _innerPadding * dpi`、`gap = _buttonGap * dpi` | 默认值 `_innerPadding=10` / `_buttonGap=4` / `BASE_BTN_H=48`（`:79-89`） |

**成因链**：拖到最小时被 `Math.Max(100, ...)` 钉在 100px（含非客户区），而客户区扣掉标题栏/边框后约 70px，再扣 `margin×2=20px` 只剩约 50px，恰好一行按钮 48px —— 看似贴合，但 AutoGrid 的列数会随拖拽过程动态变化，行数跟着跳变，内容高度与固定下限脱节，于是出现「高度已最短但四周仍有富余留白」。宽度方向同理受 `Math.Max(160, ...)` 影响。

#### 修复步骤

1. 新增 `ComputeContentSize()`：按**当前** `columns / rows`、`S = _buttonScale * dpi`、`margin`、`gap`、`BaseBtnWidth(style)`、`ExtraGap` 计算
   - 内容宽 = 最宽行的按钮宽之和 + 行内间隙；
   - 内容高 = `rows × (BASE_BTN_H × S) + (rows − 1) × gap`；
   - 窗口尺寸 = `margin × 2 + 内容 + 非客户区 (Width − ClientSize.Width / Height − ClientSize.Height)`。
2. `RecalculateSize(resizeWindow: true)`（`:871-883`）改用 `ComputeContentSize()`，移除写死的 160/100。
3. `ResizeGrip_MouseMove`（`:626`）的 clamp 改为 `Math.Max(MinAbsW, contentW)` / `Math.Max(MinAbsH, contentH)`；为避免拖拽过程中列数抖动导致尺寸来回跳，**拖拽中沿用 MouseDown 时的列数**，`MouseUp` 后再做一次贴合。
4. 保留绝对安全下限 `MinAbsW = 120` / `MinAbsH = 60`，防止窗口缩到不可见。
5. 右键菜单（现有「增加间距 / 减少间距 / 自定义间距」附近）新增「**贴合内容**」，调用 `RecalculateSize(true)` 一键复位到贴合尺寸。
6. **范围约束**：不修改 `VirtualLayoutSerializer` 的数据结构与用户已保存的布局文件；只改尺寸计算与 clamp 逻辑。

#### 涉及文件

`VirtualKeyWindow.cs`（单文件）。

#### 验收

- `AutoGrid` / `SingleRow` / `SingleColumn` / `FixedColumns` 四种布局模式下拖到最小，按钮四周留白恒等于 `margin`（默认 10px），无额外空白。
- 不同 `_buttonScale`（0.4 / 1.0 / 2.0）与不同 DPI（100% / 150%）下均贴合。
- 「贴合内容」一键生效；窗口不会缩到不可见；已有布局数据加载后不变形。
