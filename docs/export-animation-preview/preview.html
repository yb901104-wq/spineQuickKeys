设计要点（点击右上角「标注」可在图上定位）

① v2 主分页方案：新建 ExportPreviewWindow，由 MainForm._mainTabs 追加第 4 主分页承载；前 3 主分页索引、BatchCliWindow 的 3 个子页与 EnsureCopyPage() 语义零改动
② 文件多选 + 文件夹多选；「包含子文件夹」控制 AllDirectories / TopDirectoryOnly
③ 主文件需结构探测（排除 export.json / 注解 json 等非 skeleton 的 .json）
④ 点击列表 → 配对 atlas → 解析页图名 → 校验齐全 → 复用 WebView2 换数据，不白屏
⑤ 皮肤 / 动画为左列两个小列表（点选即切换、当前项高亮）；PMA / 速度 / Mix 留在右列控制条；三项均由桥接消息驱动，不修改任何源文件
⑥ 播放暂停 + 进度条 seek + 时间码；运行时状态由 JS tick 节流回传
⑦ 官方 Skeleton Viewer (Java/libgdx) 作为参考运行时的权威对照，外部进程拉起
⑧ 状态列一眼分辨可预览 / 缺 atlas / 缺页图 / 版本不支持
※ v2 变更：移除 cli-top（Spine.com 路径栏）、内层 subtabs、共享 cli-bottom，主标签 3→4；扫描/加载进度改由左列自带状态条承载，省下约 130px 全部给预览画布。主分页切走时 VisibleChanged 暂停 player、切回恢复；可从批量导出页「验证导出结果」直接跳转并灌入输出目录（D8）。
※ v3 变更：皮肤 / 动画由右列两个下拉改为左列两个并排小列表（占文件列表下方 176px，文件列表仍有约 396px），控制条瘦身为 PMA / 速度 / Mix / 循环 + 当前项摘要；metadata 回填与 setSkin / setAnimation 消息格式不变，桥接协议零改动。四种非正常状态下小列表统一置灰。
※ 画布中的角色为示意图，非真实 Spine 渲染结果；真实效果以阶段 0 技术验证后的实机截图为准。本渲染图为设计稿，不代表已实现。
