### 1.1 S1 → S3 修正摘要

设计文档 S1 的 `SetVirtualHostNameToFolderMapping` 只能把**一个** host 映射到**一个**目录，而运行时需同时提供应用嵌入资源、用户 BYO player 资源、用户导出文件三类路径（常跨盘符）。改多 host 会因 origin 不同导致 spine-player 内部 `fetch/XHR` 被 CORS 拦截。

产品采用单一同源域 `https://spinepreview.local/`：

| URL 前缀 | 来源 | 是否写盘 |
|---|---|---|
| `/host.html`、`/bridge.js` | 程序集嵌入资源 | 否 |
| `/player/<file>` | **V3.0**：用户 BYO 目录 `<root>\<major.minor>\` 或 `<root>\`；**V3.1 现行**：先查可选 BYO 覆盖目录，缺失则回退程序集内置 `Runtime.<41\|42\|43>.*` | 否 |
| `/files/<name>` | 当前文件组注册的绝对路径字典（**V3.1 起 URL 名规范化为 `skeleton.skel` / `skeleton.json` / `atlas.atlas`**，见 §9.3） | 否 |

> **施工期修正**：`/files/` URL **不得带 `?v=<ticks>` 查询串**。官方 `loadSkeleton()` 用 `config.skeleton.endsWith(".json")` 判定格式，带 query 会让 `.json` 被当作二进制 `.skel` 解析并抛 `boneData cannot be null`。缓存改由响应头 `Cache-Control: no-store` + 每次重建 player 处理。

C# 侧 `AddWebResourceRequestedFilter(..., CoreWebView2WebResourceContext.All, CoreWebView2WebResourceRequestSourceKinds.All)` → `GetDeferral()` → 后台只读 `File.ReadAllBytes` → UI 线程 `CreateWebResourceResponse`（`Cache-Control: no-store`）→ `Complete()`。阶段 0 实测 125 请求仅 1 个 404（source map，无害）；产品侧把 `.map` / `favicon.ico` 的 404 过滤掉，其余 404 才记日志。

## 4. 桥接协议（产品实现）

```
C# → JS  loadGroup { group:{ skeleton, atlas, premultipliedAlpha, skin, animation },
                     mix, speed, autoPlay }
         setSkin / setAnimation / play / pause / seek{time} / setSpeed / setMix /
         setLoop / setupPose / setDebug / dispose / probeState
         （PMA 变更由 C# 直接重建 loadGroup，不下发 JS 消息）
JS → C#  bridgeReady / ready{skins,animations,duration,skin,animation} /
         trackChanged{animation,duration} / tick{trackTime,duration,paused} /
         error{phase,reason} / state / ack
```

**官方时序坑（阶段 0 实测）**：`config.success` 在安装 track 0 **之前**触发，此时 `getCurrent(0)` 为 `null`、`duration` 读到 0。阶段 0 探针曾在 `success` 内主动 `p.setAnimation(g.animation, true)` 绕过；**产品最终实现改为只在 `success` 内设置 `p.config.animation`**（优先 `idle` → 首个 `duration>0` 的动画 → 首个动画），由官方后续分支自行安装 track，首个 `frame()` 回调再发 `ready` / `metadata`。这样避免空动画与重复安装。

**暂停态 seek**：`drawFrame()` 在 paused 时仍逐帧调用 `config.frame`，但跳过 `animationState.apply()`。桥接层在 `frame` 回调里检测 `needPose` 标志，手动 `apply()` + `updateWorldTransform()`，使暂停拖动进度条立即刷新画面。阶段 0 实测 `seek(0.4)` 回读精确为 0.400。

**rAF 驱动**：`SpinePlayer.loadSkeleton()` 由 `requestAnimationFrame` 驱动；WebView2 被覆盖 / 隐藏 / 失焦时 Chromium 会挂起 rAF。产品侧 WebView2 恒 `Visible=true`，覆盖卡片只靠 Z-order，加载期间不再显示遮挡层（只用信息条「⏳ 加载中…」），并在 `bridge.js` 用 `startBootstrapPump()` 定时调用 `player.drawFrame(false)` 兜底，直到 skeleton 就绪或报错。

## 9. V3.1 修正（AUD-042）

### 9.1 触发与两条被推翻的前提

用户真机使用反馈（非自测）：

> 「不对，我发现两个问题，需要的runtime还需要手动指定？另外，我们二进制在导出的时候为了方便添加进unity，会在导出的文件后面额外添加后缀，例如*.skel.bytes，*.atlas.txt。因为这个原因，所以我们正常导出的文件在本项目中都无法选取。但是本项目本来目的就是为了方便检查导出文件，不可能因为这个项目而额外导出一份不能直接用于unity的文件」

| # | 被推翻的前提 | 根因（不是症状） | 症状 | V3.1 处置 |
|---|---|---|---|---|
| 1 | D2 = BYO 必填，应用不打包 runtime | 把 `Spine Runtimes License Agreement` 的「每位使用者持证 + 再分发附许可与版权声明」**误读**为「禁止打包」。原文 "provided that each user of the Products must obtain their own Spine Editor license and redistribution of the Products in any form must include this license and copyright notice" 实际**允许**集成进 Products 并再分发 | 「播放资源设置」必填；未配置则预览完全无法加载，等于工具开箱不可用 | 内置三套官方 runtime + LICENSE，零配置；BYO 降为可选覆盖 |
| 2 | 导出文件只认单一扩展名 | `ExportPreviewScanner` 按单一后缀分类，未考虑 Unity 工作流为便于导入而追加 `.bytes` / `.txt` 复合后缀 | 用户**正常导出**的文件进不了列表；文件选择过滤器也不含复合后缀 | 重写分类表 + 逻辑基名配对 + 规范化 URL 名 |

> 关键约束：本工具的目的是**检查现有导出产物**，因此绝不能要求用户为了本工具额外导出一份不能直接用于 Unity 的文件。全程只读。

### 9.2 内置 runtime 与零配置
