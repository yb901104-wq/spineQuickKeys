**控制 API 实测明细**：`setAnimation('death')` 返回时长 4.933 s；`setSkin('default')` / `setSpeed(1.5)` / `pause()` / `seek(0.4)` / `play()` 全部无异常；暂停态 `probeState` 回读 `trackTime = 0.400`、`paused = True`，**证明拖动进度条在暂停时可精确定帧**。

**一个官方时序坑（已解决并写入产品桥接层）**：`SpinePlayer` 的 `config.success` 回调在**安装 track 0 之前**触发，此时 `animationState.getCurrent(0)` 为 `null`、`duration` 读到 0。首轮探针因此误判失败。修正为在 `success` 内主动 `p.setAnimation(g.animation, true)`，官方随后检查到已有 entry 便不会重复安装。产品 `assets/spine-player/bridge.js` 已固化此逻辑。

## 3. ⚠️ 技术方案修正：S1 → S3（重要）

设计文档 §4.2 推荐 **S1 `SetVirtualHostNameToFolderMapping`**。阶段 0 实际设计资源路由时发现该方案在 **BYO（D2）+ 多目录** 场景有硬性缺陷：

- 一个 `hostName` 只能映射**一个**文件夹；而运行时需要同时提供 ① 应用自身的 `host.html`/`bridge.js` ② 用户 BYO 目录的 `spine-player.js/.css` ③ 用户导出目录的 `.skel/.json/.atlas/.png`，三者通常跨目录、甚至跨盘符。
- 若改用多个虚拟域名，`NavigateToString` 的 `about:blank` opaque origin 或跨 host 的 `fetch/XHR` 会触发 CORS，spine-player 内部加载 atlas/纹理必然失败。
- 映射是 WebView2 全局的，切目录需重设且缓存失效难控（文档 P1-2 已预判）。

**改用 S3：同源 `WebResourceRequested` 拦截**（阶段 0 已实测通过）：

```
https://spinepreview.local/host.html   ← 嵌入资源
https://spinepreview.local/bridge.js   ← 嵌入资源
https://spinepreview.local/player/*    ← 用户 BYO 目录（按 <major.minor> 版本子目录）
https://spinepreview.local/files/*     ← 当前文件组注册的真实绝对路径字典
```

- `CoreWebView2.AddWebResourceRequestedFilter("https://spinepreview.local/*", CoreWebView2WebResourceContext.All, CoreWebView2WebResourceRequestSourceKinds.All)`
- 事件内 `GetDeferral()` → 后台线程只读 `File.ReadAllBytes` → 回 UI 线程 `CreateWebResourceResponse(...)`（带 `Content-Type` / `Cache-Control: no-store`）→ `deferral.Complete()`
- 全部请求**同源**，无 CORS；无文件复制、无磁盘写入、无 base64 膨胀；天然支持跨盘符与 atlas 内相对子路径；URL 带 `?v=<ticks>` 破缓存
- 实测 125 次资源请求仅 1 个 404（`spine-player.js.map` source map，预期且无害）

**收益**：设计文档的 P1-2（跨目录/缓存失效）由"中风险"降为"已消除"；§4.2、§9 P1-2、§8 依赖表在施工文档中按此修正，设计文档 v3 保留原文作为评审记录。

## 5. 未覆盖 / 需真机确认（诚实说明）

- 阶段 0 用的是**官方示例素材**，尚未用用户真实工程导出文件验证（版本线 4.1 / 4.3、多 atlas、页图子路径、中文路径、超大 PNG）。
- `PublishSingleFile + SelfContained` 下 `WebView2Loader.dll` 自解压与"未装 SDK 机器冷启动"留到阶段 7 发布验证（EAP-014）。
- 50 次压测是 **2.1 秒内连续切换**，未做长时间（数小时）挂机与数百次切换的极限验证。
- 皮肤切换的画面变化只验证了 API 可调用，官方示例只有 1 个皮肤，多皮肤视觉效果需用户真机确认。

## 6. 决策

**GO**：D1（Web Player + WebView2）、D3（B1 重建 player 复用 WebView2）、D4（自绘控制条）三项的关键技术风险已实测排除，按 §12 推荐值进入阶段 1~5 施工。D2（BYO）通过 S3 方案落地，应用**不打包** `spine-player.js/.css`。

> **V3.1（AUD-042）决策修正注**：本报告是 V3.0 施工前的**阶段 0 门槛证据**，其技术验证结论（同源 S3 路由可行、50 次重建无 WebGL 泄漏、rAF / 暂停 seek / 二进制 `.skel` 全通过）在 V3.1 后依然成立且被复用；但其中「D2 = BYO、应用不打包 runtime」是**当时的产品决策**，不是技术限制，现已按用户反馈修正：
> - `/player/*` 优先查「高级设置」里的可选 BYO 覆盖目录，**未配置时回退到程序集内置的 4.1 / 4.2 / 4.3 三套官方 runtime**（`KeyMacro.SpinePlayer.Runtime.<41|42|43>.*`），默认零配置即可预览。
> - 合规依据：Spine Runtimes License 原文允许集成再分发（每位使用者持证 + 附许可与版权声明），应用已内置 `LICENSE-Spine-Runtimes.txt` 并提供「查看 runtime 许可」。
