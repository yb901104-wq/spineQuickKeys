## 0. 结论先行

1. **用户记忆中的官方工具确实存在，但形态与"可嵌入 Tab"不符**：`Spine Skeleton Viewer` 是基于 **spine-libgdx 参考运行时** 的 **Java 桌面程序（JAR）**，由 `java -jar skeletonViewer.jar` 或 `Spine --skeleton-viewer` 启动。它是独立窗口，不是可嵌入 .NET WinForms 的控件。
2. **同一 `spine-runtimes` 家族里存在可内嵌的等价物**：`Spine Web Player`（`spine-player.js` + `spine-player.css`，基于 spine-ts/WebGL）。其**内置控件恰好覆盖需求清单的全部 5 项**：皮肤选择、动画选择、播放/暂停、时间线拖动（scrub）、播放速度；外加 `premultipliedAlpha` 配置正好对应 **PMA 切换**。
3. **推荐路线**：以官方 Skeleton Viewer 的**功能清单与判定语义**为蓝本，用 **Spine Web Player + WebView2** 实现内嵌预览页；同时保留一个「用官方 Skeleton Viewer 交叉验证」按钮，把当前文件组交给本机 JAR 打开（libgdx 是参考运行时，是权威对照）。
4. **挂载点（v2 已调整）**：新建独立 `ExportPreviewWindow`（`TopLevel=false`），由 `MainForm._mainTabs` **追加第 4 个主分页**（index 3）承载 —— 主标签顺序变为 **快捷键 → 整理 → 批量处理 → 验证**，是导出流水线的收尾质检环节，而非"批量处理的第 4 个子功能"。`BatchCliWindow` **完全不用改**。
5. **合规结论（v4 / V3.1 修订）**：`Spine Runtimes License Agreement`（2025-04-05）原文**允许**把 Spine Runtimes 集成进 Products 并再分发，条件是「每个使用者各自持有 Spine Editor 许可证」+「再分发时附带许可与版权声明」。v1 曾据此得出「不建议打包、推荐 BYO」的结论，属**过度保守的误读**，已按用户真机反馈于 V3.1 推翻。现行实现：应用内置 4.1 / 4.2 / 4.3 三套官方 `spine-player.js/.css` 与 `LICENSE-Spine-Runtimes.txt` 全文，**开箱即用、零配置**，应用内提供「查看 runtime 许可」；BYO 降级为「高级设置」里的可选覆盖。详见 §8.2、§12.1 与 `施工文档.md` §9。
6. **为什么从子页改为主分页**（评审结论）：
   - **数据对象不同类**：前 3 个子页输入都是 `.spine` 工程、都调 CLI 或复制、都会写磁盘；预览输入是**导出产物**（`.skel/.json` + atlas + png），不调 CLI、全程只读。
   - **顶栏误导**：子页方案被迫继承 48px 的「Spine.com 路径」顶栏，而预览根本不需要它。
   - **宿主链更短**：`MainForm → TabPage → BatchCliWindow(非顶层) → TabPage → WebView2` 变为 `MainForm → TabPage → ExportPreviewWindow(非顶层) → WebView2`，少一层 Form、少一层 Tab。WebView2 是独立 HWND，父链越深，焦点 / DPI / 渲染恢复越易出问题；项目 V2.92 注释已专门记录过"两层非顶层 Form 嵌套"的创建/关闭时机坑。
   - **画布多约 130px**：省掉 cli-top 48 + subtabs 38 + cli-bottom 44。
   - **播放生命周期可控**：可在窗口 `VisibleChanged` 精确暂停/恢复 player，主标签切走后不空转 GPU；子页方案随两层容器一起隐藏，WebGL 恢复不可控。
   - **代价诚实说明**：打破 v1 的「`MainForm` 零改动」边界（约 10 行改动：1 个字段 + 1 个 TabPage + `AddRange` 追加 + `EnsureEmbeddedPage` 的 index 3 分支 + `DisposeEmbeddedPages` 一行清理），并动一次 `UiTheme.cs` 新增 profile 枚举。实际风险低，因为全部照抄 index 1/2 的现成写法；主标签由 3→4 与 V2.92「4→3」方向相反，但那次合并的是**同类**批量文件处理，这次是**异类**质检环节，不违背收敛原则。
   - **动线补偿**：导出完需多切一次主标签。建议在批量导出页加「验证导出结果」按钮，点击后跳到第 4 主分页并**自动把输出目录灌进预览列表**（§12 D8），反而比子页方案更顺，不用重新选目录。

> ⚠️ 本文档是评审稿。**在用户确认前，不新增 NuGet 包、不改 `.csproj`、不改任何 `.cs`、不递增版本号、不建 AUD 台账条目、不写施工文档。**

## 1. 官方工具调研结论（事实澄清）

### 1.1 Skeleton Viewer 是什么

来源：`http://zh.esotericsoftware.com/spine-skeleton-viewer`

| 维度 | 官方事实 |
|---|---|
| 定位 | 加载并显示导出后的 skeleton 数据，用于**验证导出数据能否被 Spine Runtime 正确渲染** |
| 内核 | **spine-libgdx**（Spine 参考运行时），非 Web、非 .NET |
| 形态 | Java 9+ 的独立 **JAR**；也由 Spine 启动器 `--skeleton-viewer` / `--sv` 拉起 |
| 版本 | 提供 2.1 / 3.5~3.8 / 4.0 / 4.1 / 4.2 / **4.3.39-beta** 等 JAR，**必须与导出时的 Spine 编辑器版本一致** |
| 输入 | `Browse` 或拖放打开 `.json` 或 `.skel`；**在数据文件同目录查找同名 `.atlas`**（`raptor.json` → `raptor.atlas`）；找不到 atlas 时用半透明白块代替 |
| 附加行为 | 监控数据/atlas 文件变化并**自动重载** |
| 交互 | 右侧黑色区域点击拖动平移；`Scale` / `Flip` / `Debug`；`Premultiplied` 勾选；`Animation` 列表（切换用 AnimationState 交叉淡入）；`Mix` 滑块；`Setup Pose` 重置 |
| 源码 | 官方提供 `SkeletonViewer.java`，并明确写明「可根据该代码创建或定制适合特定需求的工具」 |

**关键判定**：官方 SV 的 UI 里**没有 skin 切换、没有时间线拖动进度条、没有显式播放/暂停按钮**（选中动画即直接播放，靠 `Mix` 混合）。用户列出的 5 项功能中，只有「动画切换」「PMA」在 SV 中原生存在，其余 3 项（skin / 播放控制 / 进度条拖动）属于**超出官方 SV 的扩展需求**。

**根因说明（为什么不把 JAR 直接嵌进 Tab）**：Java 的 LWJGL/OpenGL 画布是独立原生窗口，通过 `SetParent` 强塞进 WinForms 会失去消息循环、DPI 与焦点一致性，且无法随 Tab 切换显示/隐藏、无法响应 `UiTheme`。这属于**架构形态不兼容**，不是配置或参数问题。

### 1.2 可内嵌的官方等价物：Spine Web Player

来源：`http://zh.esotericsoftware.com/spine-player`

| 维度 | 事实 |
|---|---|
| 组成 | `spine-player.js`（逻辑）+ `spine-player.css`（UI），基于 **WebGL** |
| 引入 | UNPKG CDN `@esotericsoftware/spine-player@4.2.*/dist/iife/spine-player.js`，或自行下载/从 `spine-ts` 仓库构建后本地托管 |
| 初始化 | `new spine.SpinePlayer("container", { skeleton, atlas, ... })`；`skeleton` 接受 `.json` 或二进制 `.skel`，`atlas` 接受 `.atlas` |
| 版本 | URL 中的 `4.2` **必须与导出时的 Spine 编辑器版本匹配** |
| 资源约定 | `.atlas` 内引用的页图片**相对 `.atlas` 路径加载**；`.png` 需与 `.atlas` 同路径 |
| 离线注入 | `rawDataURIs` 可把 `.json/.skel/.atlas/.png` 以 base64 data URI 直接内嵌，绕过 URL/CORS |
| 生命周期 | `loading` / `success` / `error` / `frame` / `update` / `draw`；`success` 后 `player.skeleton`、`player.animationState` 可用 |
| 文档化 API | `player.setAnimation(name, loop)`、`player.skeleton`、`player.animationState` |

**内置控件（`showControls: true`）能力**：

| 用户要求 | Web Player 内置控件 | 对应配置 |
|---|---|---|
| skin 切换 | ✅ 从可用皮肤列表选择 | `skin` / `skins` |
| PMA 切换 | ✅ 渲染假设切换（勾选/取消，语义同 SV 的 `Premultiplied`） | `premultipliedAlpha`（默认 true） |
| 动画切换 | ✅ 从可用动画列表选择，带 `defaultMix` 交叉淡入 | `animation` / `animations` / `defaultMix` |
| 播放功能 | ✅ 暂停/恢复 + 播放速度 | 控件内置 |
| 拖动进度条 | ✅ Scrub the timeline | 控件内置 |
| （附赠）调试视图 | ✅ regions / meshes / bones / bounds / paths / clipping / points / hulls | `debug` |
| （附赠）骨骼拖拽、全屏、背景色 | ✅ | `controlBones` / `backgroundColor` / `alpha` |

### 1.3 三条路线对比

| | A. 官方 JAR 外挂 | B. Web Player + WebView2（推荐） | C. spine-csharp 自绘 |
|---|---|---|---|
| 内嵌进主分页 | ❌ 不能 | ✅ 能 | ✅ 能 |
| 点击列表无缝切换 | ❌ 每次重启/另开进程 | ✅ 复用 WebView2，JS 换数据 | ✅ 换 SkeletonData |
| skin / PMA / 动画 / 播放 / 进度条 | 部分（缺 skin、播放、进度条） | ✅ 原生全有 | ⚠️ 全部自研 |
| 额外依赖 | Java 9+ / JAR | NuGet `Microsoft.Web.WebView2` + WebView2 Runtime + 前端 JS/CSS | spine-csharp + 自写渲染器 |
| 与深灰主题一致 | ❌ Java 原生窗口 | ⚠️ 官方控制条为浅色，需覆盖 CSS 或自绘 | ✅ 完全自绘 |
| 官方性/权威对照 | ✅ 参考运行时 | ✅ 同为官方 spine-runtimes | ✅ 同为官方 runtime |
| 工作量 | 低 | **中** | 高 |

**推荐 B，并把 A 保留为一个「交叉验证」按钮**（成本极低：`Process.Start("java", "-jar sv.jar <当前主文件>")`，路径让用户配置）。这样既拿到了"官方检测工具"的权威语义，又满足内嵌 + 无缝切换。

> 挂载方式（主分页 vs 子页）不改变上表的技术选型结论，只影响宿主链深度与改动范围；对比见 §0 第 6 条与 §3.1。

### 4.2 本地资源加载（决定成败的一环）

Web Player 默认按 URL 加载资源，直接 `file://` 会触发 CORS / 本地文件访问限制。两条候选：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **S1（推荐）虚拟域名映射** | `CoreWebView2.SetVirtualHostNameToFolderMapping("spinepreview", <目录>, Allow)`，JS 用 `https://spinepreview/<相对路径>/hero.json` | 零复制、完全离线、无 CORS、大 PNG 无内存放大、天然支持多页图 | 映射是 WebView2 全局的，跨目录切换需重设/或映射一个共同根；需验证缓存失效 |
| S2 `rawDataURIs` base64 | C# 读文件 → base64 → `PostWebMessageAsJson` 注入 | 精确控制"只加载本组文件"、无目录映射烦恼 | 多张大 PNG 时消息体积/内存≈1.33×，切换频繁有 GC 压力 |

**推荐 S1**，并把"共同根"取为所有已选主文件路径的**最长公共父目录**（`Path.GetRelativePath` 生成相对 URL）。若跨盘符无共同根，退化为 S2 或按组重设映射。

### 4.3 无缝切换的桥接协议

```
C# → JS   webView.CoreWebView2.PostWebMessageAsJson({
            type:"loadGroup",
            group:{ skeleton:"https://spinepreview/.../hero.json",
                    atlas:"https://spinepreview/.../hero.atlas",
                    premultipliedAlpha:true, skin, animation },
            version:"4.2" })
JS  → C#   chrome.webview.postMessage({
            type:"ready" | "error" | "metadata" | "tick",
            skins:[...], animations:[...], duration, trackTime, reason })
C# → JS   setSkin / setAnimation / setPma / play / pause / seek(t) / setSpeed
JS  → C#   tick（节流 ~100ms，驱动 TrackBar）
```

> **v3 补充（皮肤/动画列表化）**：`metadata` 消息里的 `skins[]` / `animations[]` 回填目标是**左列两个小列表**，不是下拉。C# 收到 `metadata` 后清空两个列表 → 逐项 `Items.Add` → 把该组默认皮肤/动画设为选中项并 `EnsureVisible()` → 更新标题栏的「N 项」计数。用户点选列表项时照样下发 `setSkin` / `setAnimation`，**消息格式与下拉方案完全一致，桥接协议零改动**；差别只在 WinForms 侧的呈现控件与事件（`SelectedIndexChanged` 而非 `ComboBox` 的 `SelectedIndexChanged`，本质同一事件）。

切换策略两种，请评审时拍板（见 §12 D3）：

- **B1 重建 player**：`showControls:false` → 清空容器 → `new spine.SpinePlayer(...)`。实现简单、状态干净。
  - ⚠️ **风险**：官方文档**未列出 `dispose()`**（源码/社区示例中疑似存在，需按选定版本的 `spine-player.d.ts` 核实）。若销毁不彻底，反复切换可能泄漏 WebGL 上下文（浏览器通常上限 ~16 个）。必须做 50 次连续切换的泄漏压测；不达标则改 B2。
- **B2 换数据不换 player**（官方论坛 `switchSkeleton` 思路）：预加载 atlas/json → 替换 `player.skeleton` / `player.animationState` → `player.setViewport()`。真正零重建，但 atlas 纹理替换与视口重算更复杂。

> 无论哪种，**WebView2 实例复用、不 `Navigate` 重载**，避免白屏闪烁——这是"无缝"的可验收定义。

### 4.4 控制条：两条路线（关键外观决策）

| | A. 官方内置控制条 `showControls:true` | **B. 自绘控制条（推荐）** |
|---|---|---|
| 开发量 | 极低，5 项功能全白拿 | 中：需 JS 桥接 + WinForms 控件 |
| 外观 | 官方 CSS（浅色/半透明），与项目深灰主题**冲突** | 完全贴合 `UiTheme`，与其余主分页 / 批处理页一致 |
| 进度条 | 官方 scrub，C# 侧无法读取/驱动 | TrackBar 可精确 seek，可显示 `00:00.433 / 00:01.200` |
| PMA 开关 | 无对应 UI 开关（只是初始化配置） | 独立开关，随时切换 |
| 皮肤/动画呈现 | 官方弹层（下拉） | **v3：左列两个并排小列表**（用户指定）；选项由 `metadata` 回填，点选即切换，当前项高亮 |

**推荐 B**：`showControls:false` + 自绘控制条，理由是主题一致性与 PMA 实时切换。但 B 依赖若干**官方文档未列出的运行时 API**（`player.play()` / `player.pause()` / `player.paused` / `player.time` / `entry.trackTime` / `dispose()`）。这些在社区示例与 spine-ts 源码中可见，但**必须在选定版本上先做 API 探针验证**（见 §9 P0 项）。若探针失败，回退 A（用官方控制条 + 仅 PMA 用外部开关触发重建）。

#### 4.4.1 v3：皮肤 / 动画为什么不放下拉

| 维度 | 下拉（`DarkComboBox`） | **两个小列表（v3 采用）** |
|---|---|---|
| 可见性 | 需点开才知道有哪些皮肤/动画 | 全部选项常驻可见，一眼看到数量与命名 |
| 切换成本 | 展开 → 滚动 → 选中（3 步） | 直接点选（1 步） |
| 当前项 | 只在收起状态显示 | 列表内青色高亮，位置一目了然 |
| 多动画场景 | 弹层高度受限，长列表难浏览 | 列表自带滚动条，可容纳数十个动画 |
| 空间 | 控制条占 2 个 118px 下拉 | 占用左列文件列表下方约 **176px**（两个 168px 卡片）；左列原本有大量空白，实际不挤压（文件列表仍约 396px / 13 行可见） |
| 控制条 | 第一行被两个下拉占满 | 瘦身为 PMA / 速度 / Mix / 循环 / Debug + 当前项摘要，进度条独占一行更宽 |
| 复用 | `DarkComboBox` | `StyleListView()` / 主题化 `ListBox`，同为 `UiTheme` 已覆盖控件 |
| 代价 | 无 | 长名称可能截断（→ 省略号 + ToolTip）；动画很多时列表需滚动（→ 可加过滤框，列 V2） |

**结论**：技术上没有任何阻碍——`metadata` 回填机制、`setSkin` / `setAnimation` 下发消息都不变，只是把 `ComboBox.SelectedIndexChanged` 换成 `ListBox.SelectedIndexChanged`。空间上左列文件列表原为约 570px 且 10 行数据只占 297px，拿出 168px 后仍约 400px，完全够用；**右列画布高度不受影响**（控制条行数不变，只是内容重排）。

### 4.5 PMA 切换语义

- 官方语义：`Premultiplied` / `premultipliedAlpha` 改变的是**渲染器对纹理 alpha 的解释假设**，不更换文件。资源本身若不是 PMA，勾选后会出现黑边/接缝——这**正是要检测的异常**。
- 因此开关 = 改配置 + 重载当前组（或重建 player），**不复制/不修改任何导出文件**。
- 可选增强：若同目录存在成对的 `-pma` 资源（如 `hero-pma.atlas` + `hero-pma.png`），在开关旁提供「配套 PMA 资源」提示，允许切换到该组做 A/B 对照。此项建议列为 V2 增强，不进首版。

### 6.2 交互流程

1. 选文件/选文件夹 → 扫描（**本页左列底部状态条**显示进度 + 取消，逻辑沿用 `InplaceBackupService.ScanAsync` 的异步/取消/上限模式）→ 填充列表，默认**不自动播放**。
2. 点列表行 → 高亮 + 右侧信息条更新 → 解析文件组 → `loadGroup()` → 画布淡入。加载中显示骨架占位 + 「正在加载 hero.json…」。
3. 加载成功 → `metadata` 回填**左列皮肤 / 动画两个小列表**（清空 → 逐项添加 → 选中该组默认项 → `EnsureVisible()` → 更新标题计数与右列「当前：skin / animation · 时长」摘要），进度条时长更新，`tick` 开始驱动。
4. 切换到另一行 → 暂停并释放旧 player，加载新组；**两个小列表清空并重填**（皮肤/动画重置为该组默认值、滚动回顶部），**保留**用户选择的播放速度、PMA 开关与循环设置。点选列表项即直接下发 `setSkin` / `setAnimation`，无需展开下拉或二次确认；名称过长时省略显示，鼠标悬停用 ToolTip 给出全名。
5. 加载失败 → 画布内错误卡片（原因 + 缺失文件清单 + 「打开所在文件夹」），不弹模态框打断浏览。
6. 「用官方 Skeleton Viewer 打开」→ 校验 JAR/Java 路径配置，拉起外部进程并传入当前主文件绝对路径；未配置时给一次设置引导。
7. **主分页切走 / 切回**：`ExportPreviewWindow.VisibleChanged` 触发 `SpinePlayerHost.Pause()` / `Resume()`，暂停时保留当前 `trackTime` 与所选 skin / animation / 速度，切回后从原帧继续；避免切走后 WebGL 空转 GPU。这是主分页方案相对子页方案的关键增益。
8. **（D8 可选）从批量导出页跳转**：点击「验证导出结果」→ `MainForm.NavigateToPreview(outputDir)` → 切到主分页 index 3 → 触发 `EnsureEmbeddedPage(3)` 懒加载 → 把输出目录灌进预览列表并自动扫描，无需重新选目录。

### 6.3 渲染图状态

`preview.html` 右上角可切换 5 种状态，便于评审：**正常预览 / 缺 atlas 警告 / 加载中 / 版本不匹配 / 空列表**，并带标注模式说明设计要点。v2 渲染图已按主分页方案重绘（4 个主标签、无内层子页栏）；**v3 再按皮肤/动画小列表方案重绘**（左列新增两个并排列表、右列控制条去掉两个下拉改为摘要行、四种非正常状态下小列表统一置灰）。小列表项在渲染图里可点击切换高亮，便于直观感受交互。

## 9. 风险与未决事项

| ID | 等级 | 风险 | 影响 | 应对 |
|---|---|---|---|---|
| P0-1 | 高 | `play/pause/paused/dispose/seek/trackTime` 等 API **官方文档未列出**，仅社区示例/源码可见 | 自绘控制条方案 B 可能落空 | 施工前先做 **API 探针**：下载目标版本 `spine-player.js` + `.d.ts`，逐项验证；不通过则回退官方内置控制条（方案 A） |
| P0-2 | 高 | 重建 player 的 WebGL 上下文泄漏 | 连续切换后画布变黑 | 50 次连续切换压测；不达标改 B2「换数据不换 player」或每次重建 WebView2 + 遮罩 |
| P0-3 | 高 | 版本线必须与导出版本严格一致 | 4.1 导出用 4.2 player 会加载失败 | 从 skeleton 数据自动读版本 + 按 `<major.minor>` 找资源 + 缺失时明确阻断并给指引 |
| P1-1 | 中 | 单文件发布下 WebView2 加载器/运行时 | 用户机器打不开预览 | 发布后独立机器验证；写运行时探测与下载引导 |
| P1-2 | 中 | `SetVirtualHostNameToFolderMapping` 跨目录/缓存失效 | 切换后加载到旧文件 | 共同根策略 + 每次切换带 `?v=<ticks>` 破缓存；必要时退 S2 |
| P1-3 | 中 | atlas 命名变体（`-pma`、`.atlas.txt`、页图子路径、多 atlas） | 误判"缺页图" | 配对规则做可配置 + 扫描结果详情面板展示实际命中路径 |
| P1-4 | 中 | 大目录扫描卡顿 | UI 假死 | 复用 `InplaceBackupService.ScanAsync` 的异步/取消/上限模式，进度显示在本页左列状态条（**不再有共享底栏**） |
| **P1-5（v2 新增）** | 中 | 主标签由 3→4 后，`MainForm` 最小宽度 1100 下标签文本可能挤压/换行 | 标签显示不全 | 主标签顺序保持追加式；实测 1100 / 1440 两种宽度；必要时缩短新页文本为「动画预览」或启用 `DarkTabControl` 的自动换行/省略 |
| **P1-6（v2 新增）** | 中 | 跨页跳转（D8）需要 `MainForm` 暴露导航方法，且跳转时预览窗口可能尚未懒加载 | 目录灌不进列表 | `NavigateToPreview(dir)` 内部先切 `SelectedIndex=3` → 等 `EnsureEmbeddedPage(3)` 创建完成 → 再调窗口的 `LoadDirectory(dir)`；用"待加载目录"字段兜底，避免依赖事件时序 |
| **P1-7（v2 新增）** | 中 | 主分页切走后 WebView2/WebGL 继续渲染，或切回后上下文丢失 | GPU 空转 / 画布黑屏 | `VisibleChanged` → `Pause()` / `Resume()`；阶段 0 需实测切走 30s 再切回能否恢复，失败则改为切走时销毁 player、切回时重建并恢复 `trackTime` |

| P2-2 | 低 | 官方控制条 CSS 与深灰主题冲突（若选方案 A） | 视觉割裂 | 覆盖 CSS 变量或注入自定义样式 |

## 12.1 V3.1 决策修正（AUD-042）

**触发**：用户真机使用反馈（非自测）——

> 「不对，我发现两个问题，需要的runtime还需要手动指定？另外，我们二进制在导出的时候为了方便添加进unity，会在导出的文件后面额外添加后缀，例如*.skel.bytes，*.atlas.txt。因为这个原因，所以我们正常导出的文件在本项目中都无法选取。但是本项目本来目的就是为了方便检查导出文件，不可能因为这个项目而额外导出一份不能直接用于unity的文件」

| 被推翻的前提 | v1~v3 结论 | 根因（不是症状） | V3.1 现行结论 |
|---|---|---|---|
| D2 runtime 来源 | BYO 必填，应用**不打包** `spine-player.js/.css` | 把 Spine Runtimes License 的「持证 + 附许可声明」误读为「禁止打包」，属过度保守；症状是「播放资源设置」必填、未配置则完全无法预览 | 许可证允许集成再分发 → **内置 4.1 / 4.2 / 4.3 三套官方 runtime + LICENSE，零配置**；BYO 仅作「高级设置」可选覆盖 |
| 导出文件后缀 | 只认 `.skel` / `.json` / `.atlas` / `.png` 单一扩展名 | 按单一扩展名分类，未考虑 Unity 工作流为便于导入而追加 `.bytes` / `.txt` 复合后缀；症状是用户正常导出的文件根本进不了列表 | 支持复合后缀，**不要求用户为了本工具额外导出一份不能直接用于 Unity 的文件** |

### 12.1.1 内置 runtime 清单

| 版本线 | npm 包版本 | `spine-player.js` | `spine-player.css` | 嵌入资源名前缀 |
|---|---|---|---|---|
| 4.1 | `@esotericsoftware/spine-player@4.1.55` | 563466 B | 27395 B | `KeyMacro.SpinePlayer.Runtime.41.*` |
| 4.2（默认） | `@esotericsoftware/spine-player@4.2.120` | 608081 B | 27395 B | `KeyMacro.SpinePlayer.Runtime.42.*` |
| 4.3 | `@esotericsoftware/spine-player@4.3.13` | 691764 B | 29602 B | `KeyMacro.SpinePlayer.Runtime.43.*` |

- `KeyMacro.csproj` 用**显式 `LogicalName`** 逐个嵌入，不用 `**` glob：三套文件名同名、目录名带点，glob 会产生资源名歧义。
- 资源仍走 §4.2 修正后的 **S3 同源 `WebResourceRequested`**：`/player/<file>` 先查可选 BYO 覆盖目录，缺失则读程序集嵌入资源；`/host.html` / `/bridge.js` / LICENSE 恒走嵌入资源；`/files/<name>` 走当前文件组绝对路径字典。
- 合规：内置 `LICENSE-Spine-Runtimes.txt`（2025-04-05 版全文），「高级设置」→「查看 runtime 许可」可直接阅读；每位使用者仍须各自持有 Spine Editor 许可证。

### 12.1.2 Unity 复合后缀识别表

| 逻辑角色 | 可识别的文件名后缀 | 说明 |
|---|---|---|
| 骨骼主文件（二进制） | `.skel.bytes`、`.skel` | `LogicalStem` 均为去掉后缀后的基名 |
| 骨骼主文件（JSON） | `.json.txt`、`.json.bytes`、`.json` | 同上 |
| atlas | `.atlas.txt`、`.atlas` | 支持 `-pma` 变体组与 `StripKnownSuffix` 基名匹配 |
| atlas 声明的页图 | `.png`、`.png.bytes`、`.png.txt` | 按 atlas 内声明名 + 三种实际文件后缀解析 |

- `hero.skel.bytes` / `hero.json.txt` / `hero.skel` 的 `LogicalStem` 均为 `hero`，因此可与 `hero.atlas.txt` / `hero.png` 正确配对。
- **URL 名规范化**：交给 Web Player 的 URL 统一为 `skeleton.skel` / `skeleton.json` / `atlas.atlas`，页图用 atlas 内声明名。原因是官方 `loadSkeleton()` 按 `config.skeleton.endsWith(".json")` 判定格式，磁盘真实名带 `.bytes` / `.txt` 会被判错；真实路径经 `SpinePlayerHost._fileMap` 映射到规范化 URL 名，磁盘文件**不复制、不改名**。
- 只读红线不变：扫描 / 解析 / 预览全程 `File.ReadAllBytes` / `File.ReadAllText`，不在源目录生成任何文件。

### 12.1.3 实施中暴露并修复的跨版本问题（V3.0 设计稿未预见）

1. **4.1 配置字段不兼容**：4.1 `validateConfig` 只认 `jsonUrl` / `binaryUrl` / `atlasUrl`；4.2 兼容新旧两套；4.3 主认 `skeleton` / `atlas`。`bridge.js` 同时下发全部字段并按 URL 结尾填 `jsonUrl` 或 `binaryUrl`，否则 4.1 抛 `A URL must be specified for the skeleton JSON or binary file.`。
2. **4.1 真实工程「状态就绪但画布空白」**：用户 4.1.24 工程的 `default` 皮肤几乎无附件，附件集中在具名皮肤中；4.1 runtime 在空 `default` 上计算 viewport 得到 `x=100000000` / NaN，camera 亦为 NaN。修复为三处联动：自动选「附件最多的皮肤」、首帧检测非有限 viewport 后 `setViewport()` 重算、切换文件时清空继承的皮肤 / 动画选择。
3. **诊断接口**：`bridge.js` 有意保留只读 `window.__eapPlayer` / `window.__eapCfg`，供后续真机排查；不提供远程入口、不写回文件。
