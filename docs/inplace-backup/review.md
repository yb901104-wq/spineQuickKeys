## 2. 根因与症状（先分清，避免只打补丁）

**根因**：首次版把「批量复制到目的地」的现有范式（`BatchCopyService` + `ConflictDialog`）当作可直接复用的基线。但该范式服务于**把文件写到别处**，天然带有「创建目录 / 允许覆盖 / 默认 Overwrite / catch 后仅 done++」的语义；而本次需求是**在原目录生成副本**，两者安全语义正好相反。同时，安全约束被写成零散的校验条目，没有形成**不可绕过的不变式**，任何一条漏实现都会破坏红线。

**症状**：覆盖按钮与 `overwrite:true`、后缀空值导致自覆盖、目标撞上另一个源文件、扫描 API 与「不跟随链接」自相矛盾、失败计数缺失、勾选框可能不显示等。

**处置**：不复用 `ConflictAction` 语义；在服务层建立 8 条强制不变式（R2 第 6.6 节），UI 校验降级为「提前提示」而非安全边界。

## 3. 发现清单

### S1 阻断级（直接违反红线，必须改）

| 编号 | 位置 | 问题与证据 | 后果 | 处置 |
| --- | --- | --- | --- | --- |
| R-01 | 6.3 / 6.5 / 2 节 | 文档允许「覆盖」并复用 `ConflictDialog`。真实代码：`BatchCopyService.cs:55` `var action = ConflictAction.Overwrite;`、`:87` `File.Copy(..., overwrite: action == ConflictAction.Overwrite)`、`ConflictDialog.cs:7` 默认 `Overwrite`、`BatchCopyWindow.cs:716` 窗口销毁时 `return ConflictAction.Overwrite`、`BatchCopyService.cs:129-134` 枚举首项即 `Overwrite`。照抄即得覆盖能力，且默认倾向覆盖 | 可覆盖磁盘上已存在文件，违反红线 4 | 移除覆盖路径：`File.Copy(src, dest, overwrite:false)` 硬编码；契约去掉冲突回调，改为「预检自动跳过 + `BackupResult.SkippedTargets` 明细」；不复用 `ConflictDialog` |
| R-02 | 6.3 / 6.2 | 「目标文件已存在」只当普通冲突处理，未识别**目标可能就是用户已有资产或另一个勾选源文件**（如目录里本就有 `hero_bf.png`）；`dest != 任一源文件全路径` 中「任一源文件」未定义是勾选项、扫描项还是磁盘实际 | 覆盖一个未参与本次操作的用户文件 | 预检以 `File.Exists(dest) || Directory.Exists(dest)` 为唯一真相，命中即跳过；目标集合用 `OrdinalIgnoreCase` 去重 |
| R-03 | 4.4 / 6.5 | 后缀合法性只在 UI 校验，服务层 `BackupAsync(suffix)` 无二次校验；未覆盖 `Trim` 后为空、超长、Windows 保留名等。后缀为空时 6.2 公式使 `dest == src` | `File.Copy` 写向源文件自身，违反红线 2 / 3 | 服务层 `ValidateSuffix()` 前置断言（非空、Trim 后非空、无非法字符、长度上限、生成名不等于源名）；UI 仅做即时提示 |
| R-04 | 4.1 / 5 步 11 / 6.3 | 「移除选中」「清空列表」未声明只操作内存列表；「取消：不回滚」未声明「不删除」；失败时 `File.Copy` 可能留下不完整目标文件，处理未定义 | 施工者可能误实现为磁盘删除/清理，违反红线 3 / 5 | 明确写死：列表操作零磁盘 I/O；取消不删除任何文件；失败产物保留并计入汇总，禁止任何删除 |

### S2 高（可靠性 / 数据风险）

| 编号 | 位置 | 问题与证据 | 处置 |
| --- | --- | --- | --- |
| R-05 | 5 步 4 vs 6.1 | **文档内部矛盾**：5 步 4 写 `Directory.EnumerateFiles(path, "*", SearchOption.AllDirectories)`，6.1 却要求「不跟随符号链接 / 重解析点」。该重载不自动跳过 junction/symlink，可能目录环递归，也可能把**所选目录之外**的文件纳入备份 | 改用 `EnumerationOptions { RecurseSubdirectories = true, IgnoreInaccessible = true }`，逐目录检测并跳过 `FileAttributes.ReparsePoint`；扫描结果断言仍在所选根目录内 |
| R-06 | 6.5 / 5 步 12 | 契约照抄 `BatchCopyService`，但现有服务 `catch` 后只 `done++`（`:91-95`）、`Completed` 只有总数（`:107`），**没有失败计数与失败明细**；文档却要求「成功 / 跳过 / 失败」汇总 | `BackupResult` 独立维护四类计数 + 失败明细；第 11 节验收加入汇总核对 |
| R-07 | 6.3 | 目标碰撞未定义：Windows 大小写不敏感（`Hero.png` 与 `hero.png` 映射到同一目标）、两个源映射到同一目标、目标是硬链接/重解析点 | 预检用 `OrdinalIgnoreCase` 对目标去重，碰撞只保留第一个、其余计入「跳过」并在汇总说明 |
| R-08 | 5 步 10 | 进度回调未要求切回 UI 线程；现有 `BatchCopyWindow.cs:663-676` 用 `BeginInvoke`，新面板若遗漏会跨线程访问控件崩溃 | 契约明确：所有事件在 UI 线程通过 `BeginInvoke` 派发，并先判 `IsDisposed` |
| R-09 | 第 3 节 | 两 Tab 共用进度区却无互斥：Tab1 复制与 Tab2 备份可并发写同一进度条/状态栏；切到 Tab1 后 Tab2 的取消按钮不可见 | 窗口级单任务互斥：任一任务运行时另一页主按钮禁用、Tab 切换禁用、窗口级显示取消入口 |
| R-10 | 4.2 / 4.4 | 执行期间仍可改过滤 / 勾选 / 后缀，导致「用户看到的集合」与「实际执行集合」不一致 | 执行期间锁定列表、过滤与后缀输入框；执行集合在点按钮时快照冻结 |
| R-11 | 5 步 12 / 9.3 | 执行后是否刷新列表未定义；若刷新会把新生成的 `_bf` 文件带入列表，下次「全选」产生 `_bf_bf`。而 9.3 的排除规则只是「待确认」，可被用户否决后消失 | 执行后不自动刷新；手动刷新时按**强制规则**排除已是备份的文件（9.3 升级为不可关闭） |

## 7. 剩余风险 / 仍需你确认

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | 冲突策略改为「一律跳过、无覆盖」 | 这是「不能覆盖」红线下的唯一安全解，但会让重复执行同一批文件时**第二次全部跳过**。若你希望改为「自动追加序号 `_bf_2`」，需明确授权（那会引入新的命名规则，属于范围变更） |
| 2 | 强制排除已备份文件 | 目录里本就存在的 `hero_bf.png` 如果是用户资产，会被从列表排除、不显示。属预期行为，但需在 UI 提示「已排除 N 个疑似备份文件」，避免以为文件丢失 |
| 3 | 硬链接 / 重解析点 | 「目标已存在即跳过」可防住绝大多数场景；仍建议施工验收用真实硬链接用例验证一次 |
| 4 | 大小写碰撞 | Windows 不区分大小写，两个仅大小写不同的源文件会映射到同一目标，只保留第一个、其余计入跳过并在汇总说明 |
| 5 | 扫描规模上限 | 建议 20,000 文件触发提示、扫描可取消；具体阈值请你确认 |
| 6 | `ListView` 勾选框 | `UiTheme` 未处理 `DrawItem`，需实机验证；若不可见需补绘制（属 `UiTheme.cs` 的小幅修改，已列入第 8 节） |

> 本报告只审核文档，**未修改任何 `KeyMacro/` 代码**。施工仍以你明确批准为前提。
