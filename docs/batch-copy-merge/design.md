## 0. 一句话结论

把「批量复制到目的地」与「原地复制备份」合成**单页**：

- **左列**：沿用「原地复制备份」的选择文件结构 —— 源文件夹 / 后缀+关键词过滤 / 五列勾选文件列表。
- **右列**：沿用「批量复制到目的地」的目标路径结构 —— 前缀 / 中间 / 后缀 / 预览目标，改为**竖向堆叠**，与左侧文件列表**并列**。
- **右列顶部**新增一颗**独立勾选项**「原地复制」；勾选后，右侧目标路径整块**置灰禁用**，改由备份后缀决定输出名。
- 服务层**不合并**：两个引擎各走各的，开关只负责路由。

## 1. 现状盘点（以代码为准）

> **宿主形态（2026-11-09「首页标签化整合」之后，必须先看这条）**
> `BatchCopyWindow` 仍是 `Form`，但已被 `MainForm.EmbedPage()` 以 `TopLevel=false` / `FormBorderStyle=None` / `Dock=Fill` 嵌入主窗口第 3 个主标签「**批量复制**」；外层共 4 个主标签（快捷键 / 批量重命名·spine解包整理 / 批量复制 / CLI批量合并·导出），宿主 `ClientSize 1440×900`、`MinimumSize 1100×650`，嵌入页实测约 `1432×856`。
> 所以本次要合并的是**「批量复制」主标签内部的两个子 Tab**；外层 4 个主标签与首页结构**完全不动**。嵌入态下 `BatchCopyWindow.Text`、自身标题栏与自身 `MinimumSize` 都不显示/不生效，预览图按真实宿主形态绘制。

| 维度 | Tab1「批量复制到目的地」 | Tab2「原地复制备份」 |
|---|---|---|
| 页面容器 | `BatchCopyWindow` 内 `DarkTabControl` 页 0 | 同窗口页 1（`InplaceBackupPanel`，默认不选） |
| 选源入口 | `SourceFilePicker`（缩略图勾选**单文件**） | `FolderMultiSelectDialog`（**多文件夹**、递归只读扫描） |
| 源列表 | `ListBox` 单行全路径，无勾选、无过滤 | `DataGridView` 五列（勾选 / 文件名 / 类型 / 大小 / 所在目录）+ 全选/全不选 |
| 过滤 | 无 | 后缀下拉 + 文件名包含（AND、300ms 防抖，只影响显示） |
| 执行集合 | `_sourceFiles` **全量** × `GetTargetPaths()` 全量 | `_checked` **勾选快照**（含被过滤隐藏项） |
| 目标配置 | 前缀 Combo + 选择文件夹 / 中间多行 TextBox + 添加行·删除行 / 后缀 Combo + 清理历史 / 预览目标 ListBox | 无目标路径；只有「备份后缀 `_bf`」+ 命名示例 |

| 主按钮 | 底部通栏「开始复制」（运行中「取消复制」） | D 区右对齐「开始批量备份」（运行中「取消备份」） |
| 执行服务 | `BatchCopyService.CopyFilesAsync`（建目录、冲突弹窗、可覆盖） | `InplaceBackupService.BackupAsync`（INV-1~8、`overwrite:false`、目标已存在跳过） |
| 历史记录 | `PrefixHistory` / `SuffixHistory` | `BackupSuffixHistory`（独立，最近 10 条） |
| 窗口级 | 进度条 + 状态栏在 TabControl 之外共享 | 同左；另有跨 Tab 单任务互斥、禁止切页、关闭保护 |

### 1.1 关键冲突识别（排版本质 vs 语义本质）

| 表象（容易看到的） | 实质（必须拍板才能定的） |
|---|---|
| 两个 Tab 来回切换麻烦 | 合并要**拆掉 TabControl**，跨 Tab 互斥逻辑随之失效，需改为「运行中锁定模式开关」 |
| 两处都有「后缀」输入框 | 二者**语义完全不同**：一个是路径末段、一个是文件名后缀，同屏后必须区分，否则会误填 |
| 一个页面有目标路径、一个没有 | 勾选「原地复制」不是简单置灰，而是**切换执行引擎**：禁用 `BatchCopyService` 路径，改走 `InplaceBackupService`，安全红线不变 |
| 源列表样式不同 | 合并后统一用勾选列表，意味着 Tab1 原「全量文件 × 全量目标路径」的语义会变成「**勾选文件 × 目标路径**」，这是行为变更，不是排版变更 |

### 3.1 尺寸与排版参数

| 项 | 值 | 说明 |
|---|---|---|
| 宿主窗口 | `ClientSize 1440×900` / `MinimumSize 1100×650` | **不动**（`MainForm.cs`） |
| 外层主 Tab 条 | 44px，4 页，选中「批量复制」 | **不动** |
| 嵌入内容区 | 约 `1432×856`，`mainPanel` padding 8 | **不动**（`BatchCopyWindow`） |
| 页面外框 | margin 16 / padding 12 / gap 10 | **R3：保持通栏、不收窄**（宽 1408px）；框到列的 12px padding 与两列间 10px gap 均不变 |
| 左右列宽度 | 左 **816px** / 右 **556px**（各比 R2 加 56px） | **R3 调整**：把框内 112px 空白平分给两列各自拉长；用 `flex:1 1 816px` / `flex:1 1 556px` 弹性填满，窗口更宽时两列按比例一起变宽、始终不留白；窄屏时两列一起压缩 |
| 左列 A / B / C | 66 / 60 / flex（≈510px） | A、B 高度沿用 Tab2；C 吃掉移除内层 Tab 条后多出的约 34px |
| 右列 模式卡 / 目标卡 | ≈104 / flex（≈540px） | 模式卡与目标卡分离，凸显「独立选项」 |
| 框内剩余空间 | **0**（两列正好占满内容区） | R3 起不再保留框内留白；仅剩框到列的 12px padding 与两列间 10px gap |
| 底部 主按钮 / 进度 / 状态 | 48 / 56 / 24 | 均在 `mainPanel` 内、维持**通栏** 1408px，与外框对齐；进度与状态栏窗口级共享，不变 |

> 几何推导：页面内容区 = 1440 − 32 margin − 2 border − 24 padding = **1382px**，即 `左列 + gap 10 + 右列`。R2 为 `760 + 10 + 500 = 1270`，故框内余 **112px**；**R3 把这 112px 平分给两列各 +56px**，得 `816 + 10 + 556 = 1382`，正好填满。D10「左右平分」的原则保留，只是平分对象由「两侧留白」改为「两列各加的宽度」。

### 3.3 R3：不收窄外框，两列各自拉长填满（18:26 定案）

> 用户反馈「可以不用收窄了，里面的左右各自增加填满空的区域就行；当前框和左右两列之间的间隔就可以」→ **D11（外框收窄）已否决**，改为把框内空白分给两列。

| 项 | R2（D10 定稿） | D11 变体（❌ 已否决） | **R3（当前）** |
|---|---|---|---|
| `.page` 外框 | 通栏 1408px | 收窄 1296px 居中 | **通栏 1408px，不收窄** |
| 框内留白 | 左右各 56px | 0（移到框外各 72px） | **0（被两列吃掉）** |
| 左列 / 右列 | 760 / 500 | 760 / 500 | **816 / 556**（各 +56） |
| 框到列 padding / 列间 gap | 12 / 10 | 12 / 10 | **12 / 10（不变）** |
| 底部 主按钮 / 进度 / 状态 | 通栏 1408px | 收窄 1296px | **通栏 1408px，与框对齐** |

**做法**：保留 `.page` 的 `margin:0 16px` 与 `padding:12px`，去掉 R2 的 `justify-content:center`；两列改为 `flex:1 1 816px` / `flex:1 1 556px`，由它们自己撑满内容区。控件、列宽、逻辑一个都没动，只改两列容器宽度。

**诊断留痕**：18:20 观察到的「两列没占满边框」属**结构问题**而非渲染瑕疵 —— D10 只定了「留白左右平分」，没定留白相对边框的位置，导致 56px 留在带边框的 flex 容器内部。R3 把这段留白直接变成两列的宽度增量，问题消失。

**附带好处**：窄屏时不再由左列独吞压缩，两列按 basis 比例一起收缩。宿主压到 `1100` 宽时约 **`左 614 / 右 418`**（R2 是 `左 534 / 右 500` 不缩），左列「所在目录」列反而更宽；代价是右列会被压到约 418px，目标路径区控件需确认仍可用（见 D8）。

## 5. 交互规则（设计态描述，**尚未实现**）

### 5.1 模式开关两种状态

| 元素 | ☐ 未勾选（默认 · 目标路径模式） | ☑ 勾选（原地复制模式） |
|---|---|---|

| 目标卡标题右侧提示 | 无 | 「原地复制模式下不可用」 |
| 模式卡内「备份后缀 + 示例」 | **置灰禁用** | **启用**，`_bf` 校验与实时示例照常工作 |
| 主按钮 | 「开始复制」（运行中「取消复制」） | 「开始批量备份」（运行中「取消备份」） |
| 预览目标列表 | 按 `GetTargetPaths()` 300ms 防抖实时刷新 | 保留最后一次内容但整卡置灰（或显示提示，见 D9） |
| 状态栏 | 「配置目标路径后点击开始复制」 | 「勾选文件后点击开始批量备份，在原目录生成带后缀副本」 |
| 实际执行 | `BatchCopyService` → 目标路径列表 | `InplaceBackupService` → 各文件原目录 + 后缀 |

### 5.2 切换模式时的保留规则

1. **不清空**源文件夹、扫描结果、勾选状态、过滤条件 —— 切换只影响右列可用性与主按钮文案。
2. **不清空**目标路径三段输入与历史 —— 切回目标模式时原样恢复，避免重复填写。
3. 模式切换**不触发**任何磁盘 I/O；扫描仍只在点「选择文件」后发生。
4. 任务运行期间模式开关**禁用**（替代原「禁止切 Tab」），退出运行后恢复。

### 5.3 执行集合（两模式统一）

- 统一以**点按钮瞬间的勾选快照**为准；被过滤隐藏但已勾选的文件仍参与执行（沿用 Tab2 规则）。
- 目标路径模式：`勾选文件 × 目标路径列表`（原 Tab1 为全量文件，属行为变更，见 D7）。
- 原地模式：`勾选文件 → 各自原目录`，INV-1~8 全部保持。
