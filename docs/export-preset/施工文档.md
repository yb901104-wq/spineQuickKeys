## 0. 需求原文与硬边界

> 接下来，将"cli批量合成/导出"标签页改名为"批量复制/合成/导出"，下属的"合并"子标签改名为"批量合并"。另外在最后一页的"批量导出"页下，增加一个新的功能，在单图纹理按钮右边增加一个"保存为导出预设"然后在右边增加一列，作为导出预设的列表，点击"保存为导出预设"按钮，会有一个弹窗填写预设名字，确认后预设会以设置的名字保存在右边列表中。列表下方与左边按钮对齐的高度，增加三个按钮分别是"激活预设""删除预设""删除全部预设"，在列表中双击对应预设或者点击"激活预设"按钮，就可以将预设中的源目录、文件名列表中的所有文件、输出目录等信息完全录入到对应位置。另外，我需要在刷新状态右边增加一个"批量生成导出配置"按钮，功能是点击后，根据右边选择的配置名选择（包含"其他"项中手填的内容），然后利用CLI工具，在列表的每一个文件所在的目录生成一个对应名字的配置文件……最后，我发现一个问题每次选中的时候。文件列表里的export.json的状态永远是不正确的，有时候点刷新状态都不行，必须要在下面切换到其他配置文件名然后再切回来才会刷新到正常状态……最后先编写文档！然后生成预览图给我查看，由我拍板后才确认是否施工。

**U1 的官方语法复核**（施工前只读核对，未在用户工程目录写盘）：Spine 官方命令行界面文档的 Export 节明确列出
`--last-export-settings  Write the last export settings JSON from a project.`，并说明「If `--last-export-settings` is specified, `project.export.json` is generated based on the settings stored in the project file for the most recent export. If `--output` is specified, the file is saved there, otherwise it is saved next to the project file.」；Advanced 节列出 `--ignore-unknown  Don't error if a CLI parameter is not recognized.`，Unknown parameters 节说明旧启动器会拦截新参数、可用 `--ignore-unknown` 透传给编辑器。

因此本轮实现的确切命令为：

```
Spine.com --ignore-unknown -i <file.spine> -o <所在目录>\<配置名> --last-export-settings
```

#### 4.2.5 激活流程（R7）

双击列表项（`ItemActivate` / `DoubleClick`）或点「激活预设」，走**同一方法** `ActivatePreset(ExportPreset p)`：

1. 清空 `_exportEntries` 与 `_lvExportFiles.Items`（不清空预设列表、不清空顶栏 Spine.com 路径）。
2. 预设中的路径**逐个**走与 `AddExportEntry` 相同的去重与建模逻辑；文件已不存在的处理见 D12（跳过 / 保留并标红）。

#### 4.3.2 生成目标

对 `_exportEntries` 中**每一个**文件：`target = Path.Combine(Path.GetDirectoryName(entry.FilePath), configName)`。同一目录下多个 `.spine` 文件会指向**同一个**目标文件 → 需去重（D15：每个目录只生成一次 / 每个文件都调用 CLI 但跳过已存在）。

#### 4.3.3 CLI 实现路径（D0 已由 U1 拍板 = A，取消 B/C）

用户明确「必须 4.3 及以上版本才能使用」，即**接受该功能只在新版 Spine 可用**，因此取消原设计里的「模板兜底 B」与「失败自动回退 C」。实现只走真·CLI：

```
Spine.com --ignore-unknown -i <file.spine> -o <所在目录>\<配置名> --last-export-settings
```

| 要点 | 实现 |
| --- | --- |
| 官方依据 | 命令行界面文档 Export 节的 `--last-export-settings`；`-o/--output` 说明输出路径可为文件或文件夹，且该参数下「the file is saved there」 |
| 启动器透传 | 加官方 Advanced 参数 `--ignore-unknown`（旧版启动器会拦截新参数，此参数允许透传给编辑器）。**不改动** `GetProjectInfo` / `MergeSkeleton` 等既有方法里用的 `--ignore-unknown-args` |
| 目标文件名 | `-o` 直接传**完整文件路径** `<dir>\<configName>`，使产物名等于用户选的配置名（含「其他」手填值） |
| 产物命名兜底 | 若 CLI 忽略 `-o` 的文件名而在同目录生成 `<项目名>.export.json` / `project.export.json`，程序在同目录查找这些候选并 `File.Move` 成目标名。**这是 A 方案内部的命名兼容，不是模板降级** |
| 版本门槛（U1） | 按钮右侧固定备注「（必须 4.3 及以上版本才能使用）」；二次确认与失败汇总都写明「该功能需要 Spine 4.3 及以上版本」。**不做**程序化版本硬拦截（启动器版本 ≠ 编辑器版本，静态检测不可靠） |
| 失败语义 | CLI 返回非 0 / 目标文件未生成 → 记入失败清单、继续处理其余目录、汇总列出；**绝不写模板 JSON、绝不静默降级** |
| 本机限制 | 本机 Spine Launcher 4.1.10 不含该参数，无法验证真实生成；真实生成必须由用户在 4.3+ 环境真机确认 |

> S2/S3 相应调整为**只读复核 + 纯逻辑断言**：确认官方语法、确认本机版本低于门槛、用 `BuildLastExportSettingsArgs` 断言参数构造，不在用户工程目录做写盘试验，也不启动可能挂起的 Spine GUI。理由已写入 §0.3。

#### 4.3.4 执行流程（复用现有 CLI 骨架）

1. 校验：Spine.com 有效（`_cli.IsValid`）、`_exportEntries.Count > 0`、配置名非空且是合法文件名；**不要求**输出目录（与 `ValidateExportReady` 不同）。
2. `BeginCliOperation()` → `ShowProgress(true)` → 禁用 4 个相关按钮（含「保存为导出预设」？D16）。
3. 逐条 `SetProgress(i, N, $"生成导出配置: {entry.FileName}")`；`ct.ThrowIfCancellationRequested()`。
4. 每个目录一次 CLI 调用；捕获 `CliResult.Success`，失败记入 `failList` 但**继续处理其余文件**（与 `ExecuteExport` 一致，不中断整批）。
5. 结束：`ShowProgress(false)` → `EndCliOperation()` → **调用 `RefreshExportStatus()`**（关键联动，否则新生成的配置不会立刻显示 ✅）→ 弹汇总「成功 N / 跳过 K / 失败 M」+ 失败清单，写 `OperationLogger`。
6. 取消：`_cliCts` 生效，已生成文件保留、不回滚（与现有导出/打包的取消语义一致，D17）。
7. 已存在同名配置文件：D18（跳过不覆盖 / 覆盖 / 询问）。

### 4.4 R10 `export.json` 状态长期不正确 —— 根因与修复

#### 4.4.1 症状 vs 根因（务必区分）

| 层 | 内容 |
| --- | --- |
| **用户看到的症状** | 扫描/选中文件后，列表「export.json」列状态不对；点「刷新状态」也不变；必须把下面配置名单选切到别处再切回来才正常 |

| **为什么点刷新没用** | `_btnRefresh.Click → RefreshExportStatus()` 仍用错误的 `"export.json"`，所以怎么点都错 |
| **为什么切过去再切回来就好了** | 切到 demotion 触发事件 → `_exportConfigName = "demotion.export.json"`；切回 finish 再触发 → `_exportConfigName = "finish.export.json"`，字段终于与 UI 一致 |
| **加剧因素** | 字段与 UI 是两份独立状态；「其他」手填值也只写这一个字段；没有单一真值源 |

#### 4.4.2 修复方案（施工时）
