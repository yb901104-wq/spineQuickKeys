# UI 美术风格规范

## 风格关键词

深灰工作台、专业软件、紧凑面板、可辨识控件层级、低饱和工具栏、轻微圆角方框、蓝色选中态、橙色警示、青色辅助工具态。

参考图只用于提取气质：暗色界面、网格感、分区清楚、工具按钮密集但不杂乱。项目布局仍以现有功能和用户操作路径为准。

## Typography

| 层级 | 字体 | 大小 | 用途 |
| --- | --- | --- | --- |
| WindowTitle | Microsoft YaHei UI | 13-14 | 窗口标题、模块标题 |
| SectionTitle | Microsoft YaHei UI Bold | 11-12 | 面板标题、Tab 标题 |
| Body | Microsoft YaHei UI | 9-10 | 表格、按钮、标签 |
| Mono | Consolas | 9-10 | 路径、快捷键、命令参数 |
| Tiny | Microsoft YaHei UI | 8-9 | 状态、计数、提示 |

文字不随窗口宽度缩放；长路径和长文件名使用省略号，完整内容放 Tooltip 或详情区。

## Layout

- 基础间距：`4 / 8 / 12 / 16`。
- 圆角半径：普通面板 `4px`，输入框/按钮底座 `5px`，弹窗 `6px`。不使用大圆角，保持专业工具软件质感。
- 工具栏高度：`32-36`。
- 标准按钮高度：`28-32`。
- 主操作按钮高度：`34-38`。
- 面板内边距：`8-12`。
- 面板间距：`8`。
- 窗口最小宽度需要覆盖中文长按钮，不允许文本压出边界。

优先使用 `TableLayoutPanel` / `FlowLayoutPanel` / `Dock` 实现稳定响应式布局。旧固定坐标窗口在后续实现阶段应逐步替换为布局容器。

## Controls

- 按钮：外层使用更黑的圆角底座，内层按钮保留 1px 边框；主按钮用蓝色底；危险按钮用红色底；禁用态降低对比但仍保留边界。
- 按钮状态：至少准备 `normal` 与 `active/pressed` 两套图或绘制态；active/pressed 需要更亮边框、更深按下阴影或高亮色条，不能只靠文字变化。
- 输入框：外层使用更黑底座，内部暗底，边框比面板更亮；聚焦时蓝色边框。输入框必须能一眼区别于只读标签和普通面板。
- 列表/表格：列表外侧要有独立深色容器和明显边框；表头背景更深；行分隔线和选中行需要清楚。列表区域必须能一眼区别于普通面板。
- 方框：所有可视框体默认带轻微圆角，包括面板、输入框、列表容器、按钮底座、菜单、弹窗、进度条外框。只有表格内部单元格分隔线允许保持直线。
- Tab：非活动 Tab 与背景融合，活动 Tab 顶部或左侧用蓝色强调线。
- 进度条：当前处理对象独立在进度条上方；进度条内部显示 `current/total` 或百分比。
- 右键菜单：深灰背景、细分隔线、危险项红色文字或红色图标提示。
- 弹窗：统一深灰面板，标题区清晰；按钮置底，主操作在右侧，危险操作使用红色。

## Icons

- 工具按钮优先使用小图标 + Tooltip，文字用于明确命令。
- 图标线宽保持一致，颜色使用 `Text.Secondary` 或对应状态色。
- Spine 相关动作可用橙色点缀；捕获、绑定、工具类动作用青色点缀。

## Module Notes

- `VirtualKeyWindow` 保留皮肤概念，但新皮肤应与全局深灰风格一致。
- `VirtualKeyWindow` 浮窗本体、本体布局、按钮图片和 SKIN 资源本轮排除。它已有独立 SKIN 系统、按钮图片状态和布局算法；不要把普通工具窗口的主题改动直接套到虚拟按钮浮窗。
- `VirtualKeyWindow` 的右键菜单和菜单触发的输入/确认弹窗纳入统一菜单/弹窗样式。尤其是“修改按钮名称”“按钮循环延迟”“按钮间距”“删除当前按钮”“删除所有按钮”等流程，需要使用统一的深灰圆角菜单和核心弹窗。
- `BatchCopyWindow`、`BatchCliWindow`、`ReNameTool` 是批量工具，信息密度应高于普通弹窗。
- `SpineHotkeyEditor` 和 `SequenceEditor` 需要强调表格可扫描性。
- 核心弹窗需要替换 `MessageBox` 的视觉，但保留语义：信息、警告、错误、确认、危险确认。
