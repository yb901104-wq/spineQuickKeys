## 4. 技术方案

### 4.1 最小改动原则

只改 `MainForm.cs` 一个文件。`BuildUI()` 中：

- **保留**：`toolStrip`、`rootLayout`、`dgvPanel`、`listFrame`、`listTitle`、`_dgv` 的全部属性与创建代码；
- **删除**：`_btnReName` / `_btnBatchCopy` / `_btnCli` 的字段声明、`CreateButton(...)` 三行、`Click +=` 三行、`AddRange` 中的三个条目；
- **新增**：外层 `DarkTabControl` + 4 个 `TabPage`；
- **替换**：末尾 `Controls.Add(rootLayout)` → `tabShortcut.Controls.Add(rootLayout)` + `Controls.Add(_mainTabs)`；
- **不删**：`ButtonWidth()` 里对应的 `case`（保留无害，属于未改动的既有代码，避免扩大 diff）。

### 4.2 Form → TabPage 嵌入（核心代码，仅示意，施工时按此写）

```csharp
// MainForm 内新增的辅助方法：把既有 Form 原样挂到 TabPage，不碰窗体内部
private static void EmbedPage(TabPage page, Form form)
{
    form.ShowInTaskbar = false;                  // 仍在顶层态时先设，覆盖 BatchCopyWindow 构造里的 true
    form.TopLevel = false;                      // 关键：Form 才能作为子控件
    form.FormBorderStyle = FormBorderStyle.None; // 去掉标题栏/边框
    form.WindowState = FormWindowState.Normal;
    form.Dock = DockStyle.Fill;                  // 自适应填充，不改内部布局
    page.Controls.Add(form);
    form.Visible = true;
}
```

补充说明：

- `TopLevel = false` 必须在 `Controls.Add` 之前设置，否则 WinForms 抛异常。
- `Dock = DockStyle.Fill` 后，`ClientSize` 由父容器决定；`MinimumSize` / `StartPosition` 在非顶层态不生效，无需清理。
- 三个子窗体构造函数里的 `UiTheme.Apply(this, …)`、`NativeWindowTheme.ApplyDarkTitleBar(form)` 在**创建时仍是顶层窗体**，行为与现在一致。
- 该方案**不需要**把 `Form` 改成 `UserControl`，因此 R2 / R5 得以成立。

### 4.3 懒加载与生命周期

| 项 | 方案 | 理由 |
| --- | --- | --- |
| 实例化时机 | **首次切换到对应 Tab 时创建**，之后常驻复用 | ① 保持 `BatchCopyWindow.LoadHistory()` / `BatchCliWindow.LoadSavedPath()` 的初始化时机贴近「打开页面」；② 避免启动即构建 3 个重型窗体；③ 天然避开 §4.4 的主题顺序陷阱 |
| 实例持有 | `MainForm` 新增 3 个可空字段 `_renamePage` / `_copyPage` / `_cliPage` | 不重复创建，切页不丢用户已填的表单状态 |
| 触发点 | `_mainTabs.SelectedIndexChanged`（或 `Selecting`）里按需 `EnsureEmbeddedPage(index)` | 不改任何业务逻辑 |
| 退出清理 | 新增 `DisposeEmbeddedPages()`，在 `ExitApp()` 与 `MainForm_FormClosing` 的真正退出分支调用（幂等） | ⚠️ **必须显式 Dispose**：`TopLevel=false` 的 Form **不在 `Application.OpenForms` 集合里**，`Application.Exit()` 不会替你释放；同时 Dispose 会触发 `BatchCopyWindow.OnFormClosed`，把前缀/后缀历史写回磁盘（现行为是「关闭弹窗时写回」） |

### 4.4 主题顺序陷阱（必读）

`UiTheme.Apply(Form, profile)` 会 `ApplyRecursive(form)` 递归遍历**所有子控件**（`UiTheme.cs:60-71, 115-123`）。若三个子窗体在 `MainForm` 的 `UiTheme.Apply(this, Main)` **之前**就被 `Controls.Add` 进去，它们的内部控件会被 Main 主题再刷一遍（字体、`ForeColor`、Tab 的 `Appearance`/`DrawItem` 等），属于隐性外观改动，违反 R2。

⇒ **结论**：采用 §4.3 的懒加载，创建时刻必然晚于 `MainForm` 构造里的 `UiTheme.Apply`，子窗体保持自带主题，零干扰。
外层 `DarkTabControl` 在 `BuildUI()` 内创建、会被 Main 主题扫到 —— 这与三个子窗体内部 `DarkTabControl` 的现状完全一致，视觉风格统一，无需特殊处理。

### 4.5 标签文字与宽度

| 项 | 建议 |
| --- | --- |
| 标签文字 | 沿用三个按钮原文：`批量重命名/spine解包整理`、`批量复制`、`CLI批量合并/导出`，加 `快捷键` |
| 宽度 | `DarkTabControl` 构造里 `SizeMode = Fixed` + `ItemSize = 118×36`，长名称会被 `EndEllipsis` 截断。宿主**实例**上单独设 `_mainTabs.SizeMode = TabSizeMode.Normal`（不改 `DarkTabControl` 类，不影响子窗体内部 Tab），让 4 个标签完整显示。**施工修正**：WinForms 的 `TabSizeMode` 枚举只有 `Normal` / `FillToRight` / `Fixed`，初稿写的 `AutoSize` 不存在（编译报 `CS0117`），已改为 `Normal`（即按文字自适应宽度） |
