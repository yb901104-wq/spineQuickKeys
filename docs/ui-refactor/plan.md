# UI 重构总计划

## 定位

本目录记录 `KeyMacro` 的项目级 UI 重构计划。它不属于代码审核问题台账，不写入 `docs/audit.md`；只有在 UI 重构过程中发现明确功能缺陷时，才另行进入 audit。

已完成计划、规范、界面清单和高保真静态概览图。进入实际 UI 制作与替换阶段时，必须以现有代码为功能真相源，概览图只作为尺寸、布局方向和美术风格参考。

## 实施守则

- 功能优先：真实功能、按钮、菜单、表格列、事件绑定一律以当前代码为准。
- 只调整布局、默认尺寸、颜色、边框、字体、间距、控件绘制和可替换美术资源；不调整业务逻辑和功能语义。
- 概览图与真实代码冲突时，先保留真实代码内容，再记录冲突点。
- 若出现功能缺失、功能增多、按钮名称不确定、菜单项含义不确定、多个入口能否合并不确定，必须先让用户确认。
- `VirtualKeyWindow` 虚拟按钮浮窗本体、按钮图片、布局算法和 SKIN 系统默认不纳入普通 UI 替换；只处理其右键菜单和相关输入/确认弹窗。
- 每个窗口默认尺寸可参考对应概览图调整，但不得因此隐藏、删除或合并真实功能入口。
- 每批替换后需要视觉检查和基础功能入口检查，再继续下一批。

## 设计目标

- 参考 `UI美术风格参考.png` 的 Spine 专业软件气质，不参考其具体布局。
- 全项目统一深灰工作台风格：紧凑、清晰、耐看，适合长时间使用。
- 保持工具软件的扫描效率，不做营销式页面，不做大面积装饰。
- 核心弹窗统一自定义美术；系统文件选择和目录选择窗口暂保留原生。
- 批量处理模块保留清晰进度区：当前处理对象在进度条上方，进度条中间显示进度。

| 阶段 | 目标 | 产物 | 进入下一阶段条件 |

## 阶段 5 主题化准入规则

- 只能改变颜色、边框、字体、按钮状态图、菜单渲染、输入框/列表/表格视觉样式和控件间距。
- 不得新增、删除、合并、重命名真实功能入口；不得改变按钮 Click 事件、菜单项顺序含义、表格列语义或导入导出流程。
- 不得对 `VirtualKeyWindow` 本体、按钮控件、布局算法和 `skins/` 皮肤资源做普通主题化替换；只允许处理其右键菜单、托盘菜单和相关通用弹窗。
- 如果主题化需要替换控件类型（例如 `ListBox` 改 `DataGridView`、`CheckedListBox` 改表格），先记录为待确认，用户确认后再实现。
- 每次主题化后必须刷新对应运行截图和对比图，确认文字不溢出、进度文字不被进度条遮挡、危险操作仍有明确样式。

## 非目标（静态概览阶段）

- 静态概览阶段不重构 WinForms 代码。
- 静态概览阶段不替换 `skins/` 或 `icons/` 中的真实资源。
- 本轮不重构 `VirtualKeyWindow` 虚拟按钮浮窗本体、按钮图片和 VK 皮肤资源；该模块已有独立 SKIN 系统和布局逻辑，后续只在明确需要时单独处理。
- `VirtualKeyWindow` 触发的右键菜单、输入弹窗、删除确认、目标捕获结果提示等通用菜单/弹窗纳入本轮 UI 计划，因为它们属于通用交互层，不直接改变虚拟按钮 SKIN。
- 本轮不调整业务流程、快捷键逻辑、导入导出逻辑。
- 本轮不自定义系统 `OpenFileDialog`、`SaveFileDialog`、`FolderBrowserDialog`。

## 验收规则

- 每个主要模块至少有一张概览图。
- Tab 界面每个关键 Tab 单独出图。
- 核心弹窗、右键菜单、托盘菜单有统一样式概览。
- 所有概览图使用同一套深灰专业软件风格。
- 中文文字不溢出、不遮挡控件。
- 危险操作有明确警告态，不只依赖颜色表达。
- 概览图只表达未来实现方向，不作为当前功能截图。
