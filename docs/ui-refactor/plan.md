# UI 重构总计划

## 定位

本目录记录 `KeyMacro` 的项目级 UI 重构计划。它不属于代码审核问题台账，不写入 `docs/audit.md`；只有在 UI 重构过程中发现明确功能缺陷时，才另行进入 audit。

本轮只建立计划、规范、界面清单和高保真静态概览图，不修改主程序代码，不替换真实美术资源。

## 设计目标

- 参考 `UI美术风格参考.png` 的 Spine 专业软件气质，不参考其具体布局。
- 全项目统一深灰工作台风格：紧凑、清晰、耐看，适合长时间使用。
- 保持工具软件的扫描效率，不做营销式页面，不做大面积装饰。
- 核心弹窗统一自定义美术；系统文件选择和目录选择窗口暂保留原生。
- 批量处理模块保留清晰进度区：当前处理对象在进度条上方，进度条中间显示进度。

## 阶段

| 阶段 | 目标 | 产物 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| 1 | 建立界面清单 | `interface-inventory.md` | 覆盖所有主窗体、工具窗、核心弹窗、菜单 |
| 2 | 建立统一美术规范 | `style-guide.md` | 颜色、字体、控件、状态规则可直接指导实现 |
| 3 | 生成静态概览图 | `mockups/*.png`、`overview.md` | 用户确认整体风格和模块方向 |
| 4 | 拆分实现任务 | 后续 UI 实现计划 | 确认优先级、风险、测试方式 |

## 非目标

- 本轮不重构 WinForms 代码。
- 本轮不替换 `skins/` 或 `icons/` 中的真实资源。
- 本轮不重构 `VirtualKeyWindow` 虚拟按钮浮窗本体、按钮图片和 VK 皮肤资源；该模块已有独立 SKIN 系统和布局逻辑，后续只在明确需要时单独处理。
- `VirtualKeyWindow` 触发的右键菜单、输入弹窗、删除确认、目标捕获结果提示等通用菜单/弹窗纳入本轮 UI 计划，因为它们属于通用交互层，不直接改变虚拟按钮 SKIN。
- 本轮不调整业务流程、快捷键逻辑、导入导出逻辑。
- 本轮不自定义系统 `OpenFileDialog`、`SaveFileDialog`、`FolderBrowserDialog`。

## 验收规则

- 每个主要模块至少有一张概览图。
- Tab 界面每个关键 Tab 单独出图。
- 核心弹窗、右键菜单、托盘菜单有统一样式概览。
- 所有概览图使用同一套深灰专业软件风格。
- 中文文字不溢出、不遮挡控件。
- 危险操作有明确警告态，不只依赖颜色表达。
- 概览图只表达未来实现方向，不作为当前功能截图。
