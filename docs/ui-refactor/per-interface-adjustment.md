# UI 重构逐界面逐元素调整表

本表用于后续真实 UI 调整。执行顺序固定为：

1. 先确认真实功能和控件存在。
2. 再确认元素在界面中的分区。
3. 再调整尺寸、位置、间距。
4. 最后调整颜色、圆角、状态图和图标。

严禁使用全局递归主题直接套所有窗口。每个窗口必须单独核对、单独调整。

## 截图验证机制

- 已完成的真实运行截图统一保存在 `docs/ui-refactor/runtime-*.png`，不得重复临时设计一整套截图流程。
- 截图流程和截图清单见 `docs/ui-refactor/runtime-screenshot-guide.md`。
- 后续截图优先使用 `docs/ui-refactor/tools/capture-window.ps1` 捕获指定标题窗口或当前激活窗口。
- 每轮 UI 调整后只新增对应轮次截图，例如 `runtime-sequence-editor-round2-check.png`，并在对应界面小节写明检查结论。

## 当前止血规则

- `UiTheme.Apply(form, profile)` 不再自动改窗口尺寸。
- `UiTheme.Apply(form, profile)` 不再递归修改所有按钮、输入框、列表和面板。
- `UiTheme` 暂时只作为颜色/资源/菜单渲染工具保留。
- 后续若要给某个窗口套资源，必须在该窗口对应小节逐项列出后再改。

### MainForm 调整原则

- 工具栏按钮数量多，必须保证所有按钮可见可点击。
- 视觉图不能合并“选择”和“启用”：启用是 checkbox 列，选择是目标软件按钮列。
- 删除和删除全部是两个不同功能，不能合并。
- Spine 热键编辑后必须保留“释放”按钮。
- 表格列必须包含：启用、序列名称、触发快捷键、目标软件、步骤数、间隔(ms)、循环(次)、选择、清除。
- 后续布局调整优先处理工具栏换行/分组与表格列宽，不先改颜色。
